Steem content storage check

Checks that Steem API nodes return content stored the way ForkBuild stores it: in each post's json_metadata, close to 48 KB per post (docs/Protocol.md, "Proposed: Steem Content Storage"). It stores test content in this month's content thread, then reads it back from each node on its own. Posts are signed by Steem Keychain; this page never sees a key.

Image upload check

Checks that a picture can be put on a Steem post from this site: Steem Keychain signs a small test image with your posting key, and the image host stores it and returns its address. Nothing is posted on the chain.

What it does

  • Storing makes three posts (a manifest and two parts, about 48 KB each) with payout declined, so Keychain asks you to approve three times. They stay on the chain, like any stored content.
  • It uses some of your account's Resource Credits, and it needs this month's content thread.
  • Reading back needs no account. Add every node ForkBuild users are likely to read from, and read again later from a node that was down.
  • The image check uses "Your Steem account" above. Keychain asks you to approve signing the image; the image then stays on the image host.
