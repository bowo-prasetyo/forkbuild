# 09 — 签名记录与外部证据

> **高级。** 搭建、分享、改编或和朋友一起四处走走都不需要这一章：[开始玩的章节](README.md#开始玩按顺序阅读)
> 已经涵盖了这些。想知道底层运作方式时再继续阅读。

> **部分为实验性。** 签名记录页面是一项常规功能：它的列表和状态、移除无法使用的记录、在 Nostr 或 Arweave 上公告、
> 存储到 IPFS 或 Arweave、在 Arweave 上锚定，以及卡片的全部四个标签页：**快照**、**去中心化与证据**、
> **放置与 IPFS** 和**历史**。其余部分是**实验性**的：可以使用，但在以后的版本中可能会改变或移除，
> 它们生成的内容也可能无法沿用。页面会用**实验性**标记标出每个这样的部分：除 Arweave 以外的所有锚定、
> 钱包及其 Bitcoin 和 Base 步骤、Steem、Blurt、远程 IPFS 固定，以及整个**钱包与存档工具**面板。
> 指南 [11](11-EvidenceAndStorage.md) 和 [12](12-ArchiveAndAchievements.md) 会说明其中哪些部分是实验性的。
> 搭建、保存、发布到“探索”、改编、身份和对等节点都不依赖于其中任何一项。

使用 ForkBuild 不需要这些。如果你只想搭建、发布和探索，可以跳过。

**签名记录**页面是比“探索”更偏技术的一层。“探索”关注的是作品和世界；签名记录页面关注的是**签名声明**，
比如“我设计了这个结构”或“我把这个地方叫作 X”，以及你可以为声明添加的可选深度：

- **本指南**——声明从哪里来、签名记录页面、[评论](#评论)和[本地快照](#本地快照)（你的设备持有什么）。
- **[网络设置](10-NetworkSettings.md)**——网关、中继、服务和对等连接服务器。不是实验性的，对每个人都有用。
- **[证据与存储](11-EvidenceAndStorage.md)**——外部证据（Bitcoin、Base、Arweave、Steem、Blurt）、钱包流程、
  快照放置、IPFS 发布、Steem 和 Blurt。
- **[存档与成就](12-ArchiveAndAchievements.md)**——持久的观察存档、引用和成就。

## “发布”的两种含义

| | **发布**（探索） | **签名记录页面** |
|---|---|---|
| 分享什么 | 一个作品或世界 | 一条签名记录：共享世界、结构的作者身份，或地名 |
| 在哪里看到 | “探索”、你的页面（**我的作品**）、世界视图 | **签名记录**页面 |
| 能用它做什么 | 打开、探索、改编 | 检查它、获取它的内容、分发和锚定它 |
| 指南 | [发布与改编](04-PublishingAndForking.md) | 本指南 |

只**发布**不会把世界放到签名记录页面上。**与对等节点共享**才会：它会把世界签名为一个可以传给对等节点的
**共享世界**（见[来自“探索”的作品，去中心化形式](#来自探索的作品去中心化形式)）。
你发布的一切都在你自己的页面**更多 → 我的作品**（你的名字签名的作品）和“探索”中。

签名记录页面没有**打开**、**探索**或**改编**，即使是共享世界也没有。它显示的是签名记录，而不是世界。
要打开、探索或改编共享世界，请在“探索”、它作者的页面或世界视图中找到它。你从对等节点收到的共享世界，
一旦内容在此设备上，就会出现在那里。（唯一的例外是你自己需要重新发布的共享世界上的**在编辑器中打开**；见
[状态含义](#状态含义)。）

签名记录页面上的每个条目都是一条*记录*，每条记录属于以下三种之一：

| 类型 | 是什么 |
|---|---|
| **共享世界** | 一个已发布的世界，作为一条可以在对等节点和网络之间传递的签名记录 |
| **蓝图署名** | 声明你设计了某个结构 |
| **地名提议** | 为区域或地标起的名字 |

世界视图、编辑器和“探索”也把世界的签名记录称为**共享世界**，比如**我的共享世界**、**发现共享世界**和**选择共享世界**。

## 记录周围有什么

记录只是签名声明本身。你在它的卡片上、在世界视图中它的周围看到的其他一切，都是对它所做的事或附加在它上面的东西。
它们都不是记录的一种，只有记录本身是必需的：

| 术语 | 好比…… | 是什么 |
|---|---|---|
| **记录** | 书本身 | 一条签名记录：共享世界、蓝图署名或地名提议。它带有内容的哈希和发布者的签名。 |
| **内容** | 存放印刷本的地方 | 记录所涉及的字节，比如世界的积木。它们总是先保存在此设备上；**存储到 …**会把一份副本放到 IPFS、Arweave、Steem 或 Blurt 上，以便别人获取。见[内容服务](10-NetworkSettings.md#内容服务)。 |
| **快照** | 一本印刷本 | 记录内容的一份存储副本，比如世界的积木，别人可以获取并对照其哈希检查。见[本地快照](#本地快照)。 |
| **放置** | 书放在哪个书架上 | 一份说明作品立在世界中哪里的签名记录。一个共享世界可以有好几个。见[放置与改编](WorldViewAdvancedTools.md#放置与改编)。 |
| **公告 / 发现** | 图书馆目录中的条目 | Nostr、Arweave、Steem 或 Blurt 上的一条小小的签名通知，说明记录或快照存在以及它的副本在哪里，让没有与你连接的人也能找到它。见[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)。 |
| **证明 / 锚定** *（实验性，Arweave 除外）* | 公证人的印章 | 写入区块链交易（Bitcoin、Base、Arweave、Steem 或 Blurt）的内容哈希，作为它在那个时间已经存在的证据。它不存储也不公告任何东西。见[证据与存储](11-EvidenceAndStorage.md)。 |
| **评论** | 读者的书评 | 任何有名字的人都可以附在记录上的评论，每条由评论者签名，而不是由发布者签名。见[评论](#评论)。 |

所以你制作一条记录；然后，如果愿意，可以存储它的内容、公告它、锚定它，以及（对于共享世界）放置它；任何人都可以评论它。

## 记录从哪里来

你从不在签名记录页面本身上创建声明。它列出的是你在别处做出的声明、对等节点发给你的声明，以及以去中心化形式到达的
“探索”中的作品。地名提议也可以直接从 Nostr 上找到，不涉及任何对等节点；见
[附近的地名](WorldViewAdvancedTools.md#附近的地名发现任何人的提议)。

### 声明结构的作者身份

在编辑器积木库的**我的结构**中打开一个结构的**信息**面板。如果它有蓝图身份（大多数已保存的结构都有），
它的**社区署名**部分会提供：

- **声明作者身份**——以你当前的身份签署一份你设计了它的声明。在你声明之前一直显示。
- **导出署名**——把你的声明保存为一个可以交给别人的文件。
- **发布到网络**——把你的声明公告给你连接的每个对等节点，这会把它放到他们的签名记录页面上，以及你自己的页面上。

发布后，面板会提议**分发**它，让没有与你连接的人也能找到它。**分发**会打开编辑器在你发布世界后提供的同一个对话框，
只是只有签名声明那一半（作者声明没有快照）：选择它的内容存储在哪里、在哪里公告，然后点击**分发签名声明**。
**暂不**会隐藏这个提议；你以后仍然可以在签名记录页面上它的卡片中分发这个声明（见[分发](Distribution.md)）。

### 为地点命名

在世界视图中，打开某个区域或地标的命名面板，使用**发布一个名称**（见[地理位置](03-WorldView.md#地理位置)）。
这会向你连接的对等节点公告一份签名的提议。

刚发布后，面板会提议**分发**这个名称，让没有与你连接的人也能找到它，例如通过
[附近的地名](WorldViewAdvancedTools.md#附近的地名发现任何人的提议)。
选择**网络**（Arweave、Blurt、Nostr 或 Steem；默认是你的[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)）
并点击**分发**，或者点击**暂不**跳过。你以后也可以分发任何提议：打开命名面板的**更多**，在**所有提议**下点击它旁边的**分发**。
发布和分发始终是两个独立的步骤：任何一个都不会替你完成另一个。成功时会说明名称在哪个网络上公告；
失败时会显示原因，最常见的是缺少 Nostr 浏览器扩展，或者此设备上没有设置某个网络。

### 从对等节点接收

当你连接到一个对等节点时（见[对等连接与好友](07-PeerConnectionsAndFriends.md)），你的设备会收到对方发布过的一切，
而不只是在你们连接期间发布的内容。收到的声明只是一条有效签名的记录：在你用**从对等节点获取**（见下文）获取之前，
它的内容不在你的设备上。

### 来自“探索”的作品，去中心化形式

卡片中也可能是一个**共享世界**——与“探索”中的条目是同一类对象，只是包装成了适合去中心化传递的形式。
“探索”中的**与对等节点共享**会为你自己的世界创建一个（见
[与已连接的对等节点共享](04-PublishingAndForking.md#与已连接的对等节点共享)）。
一旦你在这里用**重新检查**或**从对等节点获取**解析了它，它就会加入“探索”的搜索、它作者的页面和世界视图，
并在重新加载后保留下来。

## 签名记录页面

打开**签名记录**（**更多 → 高级**）。它列出此设备编目的每一条签名记录，你自己的或对等节点的。
页面底部收起的**钱包与存档工具**面板中有三个标签页的全页工具：**区块链锚定**、**存档工具**和**引用与成就**
（见指南 [11](11-EvidenceAndStorage.md) 和 [12](12-ArchiveAndAchievements.md)）。
页面介绍中指向它的链接，以及任何需要先观察钱包的步骤，都会为你打开它。

只有在[网络设置](10-NetworkSettings.md#显示实验性工具)中打开**显示实验性工具**时才会列出这个面板；
在此之前，介绍会改为链接到网络设置。需要先观察钱包的步骤仍然会在本次访问中打开这个面板。

每张记录卡片显示：

- 它的名称，在它的内容经过检查之后：共享世界的标题或地名。否则，或者对于作者声明，显示记录的类型。
- 记录的类型（如果有名称，则在名称下面）以及发布者，缩短为对方 ID 的最后几个字符。
- 一个**状态标记**（见[状态含义](#状态含义)），每次页面加载或你点击**重新检查**时都会重新计算。
- 一行声明摘要：署名的指纹和声明者，或者地名和提议者。
- 内容不可用时显示**从对等节点获取**（没有连接对等节点时禁用）。它会依次向每个已连接的对等节点请求字节，
  并且只有在你的设备对照内容哈希检查通过后才接受。
- **重新检查**——现在重新计算状态。

下面是两个收起的部分：

- **分发**——公告记录、存储它的内容、锚定它。存储和锚定各自以你在**配置**下保存的服务对应的一个按钮开头
  （**存储到 IPFS**、**锚定到 Steem**），其他所有服务都收在**其他……选项**下。如果没有可用的已保存服务，
  会改为显示所有选项。Steem、Blurt 和远程 IPFS 固定在提供它们的地方都标记为**实验性**，除 Arweave 以外的所有锚定也是。见
  [从签名记录页面分发](#从签名记录页面分发)和[证据与存储](11-EvidenceAndStorage.md)。
- **详情**，分为四个标签页：

| 标签页 | 内容 |
|---|---|
| **快照** | [本地快照](#本地快照)：此设备持有什么，以及如何获取它。 |
| **去中心化与证据** | [去中心化](#去中心化一览)、[证据列表](11-EvidenceAndStorage.md#证据列表)，以及 Bitcoin 和 Base 交易步骤（实验性）。 |
| **放置与 IPFS** | [快照放置](11-EvidenceAndStorage.md#快照放置)列表和 [IPFS 发布](11-EvidenceAndStorage.md#ipfs-发布)（实验性）。 |
| **历史** | **显示跨领域时间线**：此设备为这条记录记下的每一次 IPFS、Bitcoin 和 Base 观察，按时间顺序排列，来自[观察存档](12-ArchiveAndAchievements.md#记录观察存档)，所以会跨访问保留；或者一条说明还没有记录任何内容的提示。 |

### 状态含义

| 标记 | 含义 |
|---|---|
| **可用** | 内容现在就在此设备上。 |
| **内容不可用** | 声明是真实的，但内容还不在这里。试试**从对等节点获取**。 |
| **记录信封无效** / **记录签名无效** | 记录格式错误，或者不是真正签名的。 |
| **内容与其自身的引用不符** / **内容无效** / **内容签名无效** | 内容与记录声称的不符。 |
| **未通过特定领域的检查** | 格式正确且已签名，但未通过针对其类型的检查。 |
| **不支持的记录类型** | 这个版本无法显示这种记录。 |

这些描述的是记录是否通过检查，而不是设计或名称好不好。

状态不是**可用**或**内容不可用**的记录不能打开、分发或锚定，所以不会给它完整的卡片。它们被集中在页面底部一个收起的组中，
“*N* 条无法使用的记录”，每条都附带状态、原因、**重新检查**和**从此设备移除**。它们也不会出现在**锚定多条记录**中。
最常见的原因是在
内容哈希改用 SHA-256 之前做出的记录：只有它的作者才能修正，方法是重新发布它。

如果其中某条是**你的**（由此设备上的某个身份签名），并且只是因为旧哈希而未通过检查，它会带着**你的**标记排在最前面。
它不会说“需要它的作者重新发布”，而是告诉你怎么做：

| 类型 | 如何重新发布 |
|---|---|
| **共享世界** | 在编辑器中重新发布这个世界，然后在“探索”中它的下方点击**与对等节点共享**（**打开“探索”**）。 |
| **蓝图署名** | 在编辑器中打开该结构的**信息**面板，点击**为此设计重新签名**，然后点击**发布到网络**（**打开编辑器**）。 |
| **地名提议** | 在世界视图中打开该地点的命名面板，再次点击**发布一个名称**。 |

对于世界，当此设备仍然保留着你发布内容的自己的记录时，卡片会更进一步：它会以世界的名字命名
（**我的城堡**，而不是**共享世界**），**在编辑器中打开**会打开那个世界，随时可以重新发布。
名字和链接来自你自己的记录，而从不来自旧条目的内容——那是没有人能检查的。如果记录已经不在了
（你之后取消发布了那个世界），卡片会像上面那样显示**打开“探索”**。

新副本会有自己的卡片；然后请移除旧的。旧的永远不会被接受，即使它是你的：此设备也会保存从对等节点收到的内容，
所以旧哈希无法证明你发布的是哪些字节。

**从此设备移除**（或者组顶部的**从此设备移除全部 *N* 条**）会先请你确认，然后在这里忘记这条记录。
它不会取消发布任何东西，也不会影响任何其他人，仍然拥有这条记录的已连接对等节点可能会再次公告它。
只有这个组中的记录可以被移除。

移除记录永远不会影响你的作品。共享世界背后的作品会留在编辑器、“探索”和你的页面（**更多 → 我的作品**）中；
只有此设备上签名记录的这份副本会被移除。要再次与对等节点共享这样的作品，请打开它、**发布**并**与对等节点共享**：
这会生成一条新记录。

### 从签名记录页面分发

**分发 → 公告 / 发现**有两张卡片：

- **记录**会在你选择的**载体**（Arweave、Nostr，或实验性的 Steem 或 Blurt）上公告签名记录本身。
  它默认使用你的[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)。
- **快照**会把内容存储到**内容**下，并在它自己的**载体**上公告，默认也是那个服务。对于世界，它是世界自己的快照，
  并且在此设备持有发布者签名的放置时，会一并公告发布者把它放在哪里，与世界视图中的**分发**相同。
  对于其他类型，它是记录的内容，只按哈希公告。此设备需要有这些字节：对于你没有打开过的世界，
  请先在世界视图中打开它，或从对等节点获取。

结果会注明使用了哪个载体，比如 **Steem：已公告**；对于世界，还会说明发布者的放置是否一并发出。
**未公告**表示只有公告失败了；内容已经存储。

## 评论

任何有名字的人都可以评论任何能够解析的记录：来自“探索”的作品、作者声明或地名。没有所有权检查、好友要求或审核。

你会在这些地方看到评论：

- 在**探索**和作者页面上：每张卡片和每个列表行上的**评论**按钮；
- 在世界视图的[我的共享世界](WorldViewAdvancedTools.md#我的共享世界分发你自己的快照无需对等节点)面板中，
  它的**评论**部分；
- 在选中的**世界相遇**上：它的**评论**按钮。

每处都会显示评论，最早的排在最前面，并附带每位作者的身份。取了名字后，你会看到一个文本框和**发表评论**；
否则会显示一条请你取名字的提示。

评论是永久的：不能编辑、删除或回复。

### 评论如何传播

从**探索**发表的评论会保存在你的设备上，发送给与你连接的对等节点，并发布到**发表评论**旁边选择的网络
（Nostr、Arweave、Steem 或 Blurt；默认是你的[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)），
让没有连接的人也能找到它。关闭这个部分（**隐藏评论**）会丢弃你输入但没有发表的内容。
从世界视图的**我的共享世界**或**世界相遇**发表的评论也以同样的方式传播，**发表评论**旁边有同样的网络选择。

要让评论不进入任何网络，请改为选择**仅本地和对等节点**。它会保存在你的设备上，并只发送给当前已连接的对等节点，
所以不需要网络账户。你发表时没有连接的人不会收到它，以后也没有人能在网络上找到它。
要让每个评论框都默认使用它，请在[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)页面的**评论**下选择它。

之后注册了网络账户，或者想把评论也发到另一个网络？在你自己的每条评论下面，有一行说明此设备已经把它发送到了哪些网络，
或者*还没有从此设备发送到任何网络*。那里的**分发**会把它发送到你选择的网络，并说明是否成功；
已经发送过的网络会被标记，不能再次发送。只有评论的作者在使用那个名字时才能看到它，因为只有作者才能为网络签署评论，
而且这一行只知道此设备发送了什么。

别人的评论会通过以下方式到达你这里：

- 来自已连接的对等节点，在发表时到达；
- 来自网络，在你打开某条记录的评论时，以及每当你点击**检查新评论**时到达。你就是这样看到自己离线期间发表的评论的。

按钮旁边的一行会报告上次检查的结果，比如*找到 2 条新评论*或*没有找到新评论*（这只涵盖有响应的网络）。
无法连接的网络会被点名（*Arweave 不可用*）；如果都没有响应，你会看到*无法连接 Nostr 或 Arweave——正在显示此设备上保存的评论*。
只有你打开评论的记录才会被检查。每条获取到的评论都会检查签名，并且不会重复计数。

当有人评论你发布的记录时，你的[通知历史](03-WorldView.md#方位与地点)（标题栏中的 🔔 按钮）中会出现一条**你的作品有新评论**。

## 本地快照

在卡片的**快照**标签页中，**本地快照**回答一个问题：此设备现在是否持有这条记录内容的字节？
它不检查签名或放置，只有在你点击某个获取操作时才会联系网络。

### 检查你有什么

**检查本地快照**（然后是**再次检查**）：

| 标记 | 含义 |
|---|---|
| **可用** | 字节在这里，并且与内容哈希相符。 |
| **不可用** | 从未在这个哈希下存储过任何东西。 |
| **哈希不符** | 这个哈希下存储着某些东西，但已经不再相符。 |

拥有同一条记录的两个人可能会得到不同的答案，因为他们的存储不同。检查之后，会有一行显示
*记录：本地已知 / 本地未知 · 快照：可用 / 不可用*：此设备是否编目了这条签名记录，以及它是否持有有效的字节。

如果检查发现没有有效的字节，会有一条提示指向下面引入字节的方法。不会自动重试任何东西。

### 引入字节

三种操作，各需单独点击：

**导入快照**——显示一个文件选择器和一个粘贴框，用于**发布快照传输包**（一条记录内容的 JSON 包）。
选择或粘贴一个，然后再次点击**导入快照**。

| 标记 | 含义 |
|---|---|
| **已导入** | 已存储，并对照其哈希检查过。 |
| **已经可用** | 相符的字节已经在这里了。 |
| **导入被拒绝** | 包中的字节与它自己的哈希不符。 |
| **快照没有被导入** | 不是有效的包。 |

**从对等节点获取快照**——选择一个已连接的对等节点，点击**从对等节点获取快照**（然后是**再次……**）。它只询问那一个对等节点。

| 标记 | 含义 |
|---|---|
| **已取得** | 对等节点的字节与内容哈希相符。 |
| **已经可用** | 相符的字节已经在这里了。 |
| **目前不可用** | 对等节点没有回应，或者没有这些字节。 |
| **已拒绝** | 对等节点的字节不相符。 |

从某个放置（见[快照放置](11-EvidenceAndStorage.md#快照放置)）**实体化快照**是第三种方法。
三者中任何一个成功后，会有一行**来源：**注明最近成功的那一个：“传输包”、“放置”或“对等节点”。

### 哪些对等节点有它？

**哪些对等节点有它？**会询问你已连接的对等节点是否持有这些字节，但不获取它们。每个已连接的对等节点都会列出并被勾选；
取消勾选你不想询问的，然后点击**询问所选对等节点**（然后是**再次询问所选对等节点**）。
每个对等节点最新的回答会连同回答时间一起显示，另有总计：**可用**、**不可用**或**无法确定**（没有及时回答）。
回答只是那个对等节点在那一刻所说的话，而不是承诺。

回答**可用**的对等节点会有自己的**从*对等节点*获取快照**按钮。它只向那个对等节点请求字节并检查它们，
与**从对等节点获取快照**相同；永远不会替你从其他任何人那里获取任何东西。**显示本次访问的回答**会列出每一个回答，
每个一行（比如 `20:21:04 — Alice → 可用`）；点击一行可以看到完整的报告、记录和内容哈希。行永远不会被改写。

### 本次访问的尝试

一旦你尝试引入字节，**本次访问的尝试**会按结果和来源统计本次访问的尝试。存储了字节的尝试并不意味着它们仍然在这里；
**检查本地快照**才能说明这一点。**显示获取历史**会列出每一次尝试（比如 `20:16 — 对等节点 → 哈希不符`）；
点击一个可以看到它的结果、记录和内容哈希。

## 去中心化一览

在**去中心化与证据**标签页中，一旦记录有了锚定或放置，**去中心化**会比较[外部证据](11-EvidenceAndStorage.md#外部证据)
和[快照放置](11-EvidenceAndStorage.md#快照放置)：

- **记录：本地已知 / 本地未知**——此设备是否编目了这条签名记录。
- 两张卡片，显示每种声明已知有多少条，以及它们对内容哈希是否一致（**一致**）或不一致（**冲突**）。
  如果一种一致而另一种冲突，会有一句话说明；一种的一致并不能为另一种担保。某种还没有声明时，会改为显示**还没有可比较的内容**。
- **与对等节点同步**（然后是**再次同步**）会向每个已连接的对等节点索取你没有的锚定和放置，并为每种报告**新声明**和**已知**。
- **显示副本已知信息**会为每个锚定和放置列出此设备是如何得知的（**获取方式**：*在本地得知*、*通过导入包得知*
  或*通过对等节点交换得知*）、**首次见到**，以及它当前的**验证** / **解析**状态。它不联系任何网络。

## 重新加载后保留什么

签名声明和记录的事实会被保留；正在进行的检查、尝试和界面则不会。

| 保留在此设备上 | 重新加载后重置 |
|---|---|
| 已编目的证据和放置，以及每一个的**本地已知信息** | **验证证据**和**解析快照**的结果 |
| 你导入、获取或实体化的快照字节 | **本地快照**中的其他一切：检查、尝试历史、**来源：**行、对等节点检查和比较 |
| **去中心化**计数（每次加载时重新计算） | **与对等节点同步**的结果 |
| — | **IPFS 发布**：服务商配置、结果、屏幕上的历史和验证历史 |
| **Bitcoin/Base 锚定记录**，在最终确定时生成 | 钱包流程的连接、资金或账户观察、计划、审核、签名、已最终确定的交易、广播结果以及屏幕上的确认或打包历史 |
| **记录观察存档**（每一次 IPFS 发布和验证、Bitcoin 广播、确认和内容证明，以及 Base 打包），直到**清空存档** | — |
| 记录引用 | 你展开了哪些卡片和行 |

重新加载后，流程或 IPFS 发布的结果仍然可以在[观察存档](12-ArchiveAndAchievements.md#记录观察存档)、
记录的生命周期，或者（对于 Bitcoin）历史 Bitcoin 锚定证据中看到。重新连接钱包，或重新配置固定服务商，即可继续。
