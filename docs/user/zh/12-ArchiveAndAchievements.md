[证据与存储](11-EvidenceAndStorage.md)中的 Bitcoin、Base 和 IPFS 工具，会把它们观察到的内容记录在此设备上的一个持久存档中。
这份指南介绍这个存档，以及建立在它之上的东西：记录之间的引用和成就。

这些卡片大多在签名记录页面的**钱包与存档工具**下，位于它的**存档工具**和**引用与成就**标签页中。
当卡片所持有的内容在重新加载后仍然保留时，每张卡片都会显示**已保存在本地**。

一个贯穿全文的用词：**记录标识**是指一条 Bitcoin 或 Base 锚定记录（见
[Bitcoin 锚定记录](11-EvidenceAndStorage.md#bitcoin-锚定记录)）。它是链上的一条记录，而不是一个人。

## 记录观察存档

在此设备上对 IPFS、Bitcoin 和 Base 工具所观察到的事实的一份持久记录。它只持有记录标识和观察：
从不包括钱包连接、密钥或固定服务凭据。

### 观察存档

**观察存档**卡片显示它持有多少条**记录**和**观察**。

- **显示存档**会打开**已存档的观察时间线**：每一次 IPFS 发布和验证、每一次 Bitcoin 广播、确认和内容证明，
  以及每一次 Base 打包观察，按时间顺序排列，每一条都注明它的领域、状态，以及（在相关时）定位符、txid 或区块高度。
  打开它不会联系任何网络。
- **清空存档**是从存档中删除任何东西的唯一方法；其他一切都只会往里添加。存档为空时它会被禁用。

### 历史 Bitcoin 锚定证据

同样的 Bitcoin 事实，按锚定 ID 分组，位于**区块链锚定**标签页中的一张卡片上。**显示历史锚定**，然后选择一个锚定 ID，
会显示它的**广播历史**、**确认历史**、**内容证明历史**、**链上位置比较**和**观察一致性**，以及汇总这五项计数的**综合证据**。
这些计数说明记录了多少，而不说明它有多可信。

### 导出、导入和查看存档

**记录存档**卡片会把存档转换成一个 JSON 文件：

- **导出存档**会显示 JSON 和一个**下载导出的存档**链接。
- **导入存档**接受一个文件或粘贴的 JSON，并预览它与当前存档相比持有多少记录和观察。
  只有**替换当前存档**才会应用它。导入会**替换**当前存档（不会合并），而且无法撤销。无效的文件会被拒绝，不会做任何更改。

**查看外部存档**会查看一个导出文件的内容而不导入它。它会显示文件的架构版本、每个领域的事实计数
（IPFS 发布和验证；Bitcoin 广播、确认、内容证明和记录标识；Base 打包和记录标识）、本地和导入的事实计数、导入事件、
它的指纹，以及它持有的 Bitcoin 锚定 ID、IPFS 记录索引和 Base 交易哈希。在那里：

- **与当前存档比较**会按领域列出哪些**相同**、**已更改**、**仅在当前**、**仅在外部**，或者**来源不同**。
- **审核替换**（在比较之后）会预览替换会改变什么，并显示两个存档的计数和指纹。它的**替换当前存档**按钮与上面的导入相同。
  替换会把每条事实都标记为新导入的，所以替换后的指纹会与文件的不同。

### 存档来源

显示事实从哪里来：**本地事实**（在此设备上观察到的）和**导入的事实**（来自某次**替换当前存档**）。
如果你曾经导入过，**存档导入**会列出每次导入的时间、事实数量和架构版本。两种事实都不会被认为更可信。

### 存档指纹

存档中每条事实和来源标记的 SHA-256 摘要。**复制指纹**会复制它。要与来自别处（比如某个对等节点）的指纹比较，
请把它粘贴到**与另一个指纹比较**下，然后点击**比较**：

| 结果 | 含义 |
|---|---|
| **一致（MATCH）** | 两个存档的内容完全相同。 |
| **不同（DIFFERENT）** | 不相同。 |
| **INVALID_FINGERPRINT** | 你粘贴的不是 64 个字符的 SHA-256 指纹。 |

一致只表示内容完全相同，而不表示内容正确，这里也不会说明哪个存档更新。

## 记录引用

记录一个记录标识指向另一个记录标识。

**记录引用 → 显示引用**会打开一个表单：从你已知的 Bitcoin 和 Base 记录标识中选择**源记录（发出引用的一方）**和
**被引用的记录（被指向的一方）**（例如“Bitcoin — a1b2…c3d4 — 内容 9f8e…”），然后点击**记录引用**。
一条记录不能引用它自己。引用只会由你创建；没有任何东西会自动创建引用，应用中其他地方的改编也不会。

引用有意不叫作改编：它记录的是指向存在这一事实，而不是它的含义（改编、引用、回复）。

已记录的引用按从早到晚列出，显示双方的链、简短标识、内容哈希以及记录时间。重复的引用会作为独立的引用保留。

**记录引用图**按记录对同样的引用分组：显示**边**、**记录**、**不同的源**和**不同的被引用者**的总数，
以及每条记录的**引出引用**和**引入引用**，它们可以展开为一条条引用。这些计数不是排名。

## 成就

记录标识在跨过某个门槛的那一刻就会获得徽章；不需要领取。

**成就 → 显示成就**会列出到目前为止获得的徽章：

| 徽章 | 图标 | 获得条件 |
|---|---|---|
| 首次发布 | 🏆 | 你的第一条 Bitcoin 或 Base 锚定记录。 |
| Bitcoin 发布者 | ₿ | 你的第一条 Bitcoin 锚定记录。 |
| Base 发布者 | 🔵 | 你的第一条 Base 锚定记录。 |
| 多链发布者 | 🌐 | 在不止一条链上有记录。 |
| 十次发布 | 🔟 | 你的第 10 条，Bitcoin 和 Base 合计。 |
| 一百次发布 | 💯 | 你的第 100 条。 |

点击一个徽章，可以看到它的**源记录**（链、内容哈希、链上引用、创建时间），以及（在可用时）**查看上方的记录生命周期**，
它会跳到那条记录的生命周期。

另外五项成就来自引用，目前还没有徽章：**首次创建引用**、**首次被引用**、**被 10 个发布引用**、**被 100 个发布引用**，
以及**首次跨链引用**（在 Bitcoin 记录和 Base 记录之间）。它们在**成就档案**中按名称列出，你可以在那里选择一个记录标识，
查看它的成就数量和完整列表，每项都注明获得时间。

成就属于记录标识，而不是人：这里没有任何东西把记录与某个人联系起来。

## 已停用：排行榜、对账和发布者标签

早期版本有排行榜页面：发布者排行榜、签名的发布者快照声明、对账工作区和排行榜，以及证据导出比较。
ForkBuild 不给人排名，也不计分（[Pillars](../../Pillars.md#what-we-are-not-making)（英文）），所以它们被移除了。
指向这些页面的旧链接会打开首页。在它们存在期间保存的存档仍然可以加载和导入，其他所有记录都会保留；
其中持有的排行榜声明和对账决定会被丢弃。

发布者关联（为那些页面给你的记录加上发布者名称标签）也被移除了。存档中持有的标签会以同样的方式被丢弃。
