> **高级。** 搭建、分享、改编或和朋友一起四处走走都不需要这一章：[开始玩的章节](README.md#开始玩按顺序阅读)
> 已经涵盖了这些。想知道底层运作方式时再继续阅读。

> **大部分为实验性。** 从卡片的**分发 → 内容**区块把内容存储到 IPFS 或 Arweave
> （[创建放置](#创建放置)和[使用偏好的服务](#使用偏好的服务)）是一项常规功能，
> 快照放置列表、Arweave 锚定和证据列表也是。这里的其他一切都是**实验性**的：其他类型的外部证据和两个钱包流程、
> 远程 IPFS 固定以及 Steem。它们在以后的版本中可能会改变或移除，它们生成的内容也可能无法沿用。
> 页面会用**实验性**标记标出这些部分。

**签名记录**页面上的每张卡片（见[签名记录与外部证据](09-PublicationsAndEvidence.md)）都有一些部分，
用来证明一条记录*何时*存在，以及把它的内容放到别人可以获取的地方：

- **[外部证据](#外部证据)**——Bitcoin、Base、Arweave、Steem 或 Blurt 上的记录，证明某条记录的内容哈希在某个时间已经存在。
- **[Bitcoin 锚定流程](#bitcoin-锚定流程)**和**[Base 锚定流程](#base-锚定流程)**——使用你自己的钱包写入一笔真实交易的分步流程。
- **[快照放置](#快照放置)**——指向内容可以从哪里获取的签名指针：IPFS、Arweave 或此设备。
- **[IPFS 发布](#ipfs-发布)**——上传到远程固定服务。
- **[Steem](#steem)**——在 Steem 上发帖、存储和分享链接。
- **[Blurt](#blurt)**——从你自己的账户在 Blurt 上发帖、存储和锚定，并获得奖励。

证据和放置回答的是不同的问题。锚定表明某个哈希在某个时间被记录下来；它不说明这些字节是否仍然可以获取。
放置说明这些字节可以从哪里获取；它不说明声明最初是何时做出的。

## 外部证据

Arweave 锚定和证据列表是常规功能。Bitcoin、Base、Steem 和 Blurt 锚定是*实验性*的，并且都有相应标记。

这里列出的锚定仅仅意味着此设备持有一条有效签名的记录，说“这已在外部被记录”。只有在你点击**验证证据**时，
才会检查这次记录是否真的发生了。页面上没有任何东西会自动验证：加载时不会，证据到达时不会，展开列表时也不会。

### 创建证据

在记录卡片的**分发**部分中，**证明 / 锚定**区块（Steem 和 Blurt 标记为**实验性**）为一键即可创建的每种证据各提供一张卡片，
每张都有自己的按钮：**创建 Arweave 锚定**和**创建 Steem 锚定**。Bitcoin 和 Base 锚定没有这样的卡片：
它们要在卡片的**详情 → 去中心化与证据**标签页中通过钱包步骤完成，区块会说明这一点。当你保存了偏好的服务时，
这些卡片会收在**其他锚定选项**下，位于那个服务自己的按钮下方（见[在偏好的服务上锚定](#在偏好的服务上锚定)）。
每个按钮都会把记录的内容哈希写入那个网络上的一笔交易，结果有三种：

| 结果 | 含义 |
|---|---|
| **已创建锚定** | 成功了。新的锚定会出现在列表中，尚未验证。 |
| **记录被拒绝** | 连接到了网络，但被拒绝了。 |
| **没有创建锚定** | 无法连接网络，或者此设备无法为它签名。 |

- Bitcoin 请使用 [Bitcoin 锚定流程](#bitcoin-锚定流程)；Base 请见[一步创建 Base 锚定](#一步创建-base-锚定)。
- **创建 Arweave 锚定**需要一个 Arweave 钱包扩展，比如 Wander。
- **创建 Steem 锚定**需要 Steem Keychain 扩展，以及在[网络设置 → Steem](10-NetworkSettings.md#steem)下设置的 Steem 账户。
- **创建 Blurt 锚定**需要 Blurt Keychain 扩展（或 WhaleVault），以及在[网络设置 → Blurt](10-NetworkSettings.md#blurt)下设置的 Blurt 账户。

在内容哈希改用 SHA-256 之前做出的记录永远不会被锚定，无论是通过这些按钮、Bitcoin 或 Base 步骤，还是**锚定多条记录**：
其他人无法对照它的旧哈希检查内容，所以对它的记录证明不了任何东西。你会在询问任何钱包之前得到**记录被拒绝**
（对于 Bitcoin 和 Base，则是失败的交易步骤），提示你重新发布它。放置也是如此，结果会是**没有创建放置**。

成功后，按钮会变成**再创建一个 … 锚定**，用于创建第二个独立的锚定。Base 锚定的创建方式不同；见
[一步创建 Base 锚定](#一步创建-base-锚定)。

**Steem 锚定比 Bitcoin 锚定弱。** 它们不收手续费，只消耗资源积分（会恢复），区块大约一分钟后最终确定。
在此之前，卡片显示**等待最终确定**，然后是**已锚定**（极少数情况下，如果链丢弃了它，会显示**未锚定**：请重新创建）。
**验证证据**在最初那一分钟会报告**无法验证**，之后会说明区块是何时、由哪个见证人记录的。**检查证据**会根据你的设备
离线检查的已签名区块头副本，立即显示区块的时间。Steem 区块由大约 21 位按权益选出的见证人签名，而不是由工作量证明保障，
所以足够多的见证人联合起来就可以改写历史；卡片会显示“由 Steem 见证人证明”。请把 Steem 锚定作为 Bitcoin 锚定之外
快速、免费的补充证据，而不是取而代之。

**Blurt 锚定**同样由 Blurt 的见证人证明，也同样比 Bitcoin 锚定弱得多。当此设备已经在 Blurt 上发布过你作品的快照
（公告了它，或存储在那里）时，那篇帖子就是锚定：**创建 Blurt 锚定**不发帖也不花费任何东西。否则，它会把作品的内容哈希
添加到你当前的 Blurt 帖子中，或者新发一篇，收取少量 BLURT 费用。最终确定、**验证证据**和**检查证据**与 Steem 相同，
卡片会链接到那篇帖子。

**在 Steem 上一次锚定多条记录。** 在**钱包与存档工具 → 区块链锚定**下，**在 Steem 上锚定多条记录**会列出你已编目的记录。
勾选你想要的（或**选择未锚定的**），然后点击**在 Steem 上锚定 N 条记录**。一次 Keychain 批准最多可以锚定 64 条。
每条记录仍然有自己的锚定，并单独验证。**在 Blurt 上锚定多条记录**的方式相同，只需一次 Blurt Keychain 批准。

### 在偏好的服务上锚定

**证明 / 锚定**区块的**配置**链接会打开[证明 / 锚定服务](10-NetworkSettings.md#证明--锚定服务)，你可以在那里选择一个默认值。
选择之后，区块会以一个以它命名的按钮开头，比如**锚定到 Steem**，它会在那里锚定，结果与上面的按钮相同。
运行时显示**正在锚定…**，完成后显示新锚定的交易和内容哈希。其他所有类型都在**其他锚定选项**下，只需一次点击。
保存偏好既不会改变那些按钮，也不会改变已有的锚定。

在没有保存任何服务、保存的服务没有在此设备上注册，或者它是 Bitcoin 时，没有这样的按钮，并且会显示所有选项：
Bitcoin 锚定要通过它的钱包步骤完成（见[Bitcoin 锚定流程](#bitcoin-锚定流程)），区块会说明这一点。

### 从对等节点发现

已连接的对等节点只会传来在你们连接期间创建或重新公告的证据。**从对等节点发现**填补了这个空缺：
它会依次询问每个已连接的对等节点，对方知道的这条记录的每一个锚定，包括对方从别人那里得知的。
页面上没有其他东西会联系对等节点。

| 提示 | 含义 |
|---|---|
| *从对等节点发现了 N 条新的证据声明。* | 它们现在在下面的列表中。 |
| *没有从对等节点发现新的证据声明。* | 这些对等节点没有新东西。这并不意味着不存在证据。 |
| *没有可以询问的已认证对等节点。* | 请先连接一个对等节点（见[对等连接与好友](07-PeerConnectionsAndFriends.md)）。 |
| *请求的对等节点发现操作无法完成。* | 在询问任何对等节点之前，本地就出了问题。 |

发现的锚定到达时是未验证的，你之前的验证结果会保留，同一个锚定永远不会被添加两次。

### 证据列表

在卡片的**去中心化与证据**标签页中，**外部证据**会显示已知有多少个锚定，并提供**从对等节点发现**（见上文）。
**显示证据**会并排列出这条记录已知的每一个锚定，即使它们相互矛盾。有多个锚定时，会先显示一个**内容绑定**摘要，
统计每个内容哈希对应的锚定数量，并在它们声称不同的哈希时发出警告。它不会说哪一个是对的。

每个锚定显示：

| 字段 | 含义 |
|---|---|
| **定位符** | 外部系统说在哪里可以找到这次记录。 |
| **已记录** | 声称的记录时间（在你验证之前只是声称）。 |
| **记录 / 内容哈希** | 这个锚定的签名把什么绑定在一起。 |
| **证明者** | 签署这个锚定的身份。 |

- **验证证据**（然后是**再次验证**）会立即向外部系统核实；见[验证结果](#验证结果)。
- **检查证据**会显示原始声明：确切的时间、定位符，对于 Bitcoin 还有区块浏览器链接和原始证明。它只读取你设备上的内容。
  底部的**本地已知信息**会说明此设备是如何得知这个锚定的：**获取方式**（*在本地得知*、*通过导入包得知*或
  *通过对等节点交换得知*）以及**这个副本首次见到**。它从不点名对等节点，也不是信任信号。

### 验证结果

| 标签 | 含义 |
|---|---|
| **已独立验证** | 外部系统确认了所声称的内容，完全一致。 |
| **证明未经独立验证** | 确实已签名，但此设备无法从外部检查这种锚定。 |
| **无法验证** | 无法连接外部系统。这与无效不同。 |
| **证据无效** / **签名无效** | 记录格式错误，或者不是真正签名的。 |
| **内容不符** | 这个锚定与这条记录不符。 |
| **外部证明无效** | 外部系统说这个声明是假的。 |

如果某个锚定在本次访问中早些时候已经验证过，而之后的检查无法连接网络，它会保留一条备注：
“这份证据之前曾经过独立验证；目前无法验证。”

Base 锚定无论是在这里创建的还是收到的，都用同一个**验证证据**按钮来验证。

### Bitcoin 锚定对账

Bitcoin 锚定的卡片还有一个 **Bitcoin 锚定**部分。**对账**（然后是**再次对账**）会提出两个独立的问题，并显示两个答案：

| 确认 | 含义 |
|---|---|
| **交易已确认** | 已打包进区块；显示区块高度、区块哈希和确认数。 |
| **交易未确认** | 没有找到，或者还没有打包（两者不作区分）。 |
| **无法获取确认状态** | 无法检查。 |

| 内容证明 | 含义 |
|---|---|
| **哈希与 OP_RETURN 相符** | 交易携带了所声称的内容哈希。 |
| **哈希与 OP_RETURN 不符** | 没有携带，或者证明格式错误。 |
| **内容证明不可用** | 无法检查。 |

已确认但 OP_RETURN 不相符的交易会如实显示。每次对账的确认结果都会加入**显示确认历史**，最早的排在最前面；
内容证明只显示最新的结果。

## Bitcoin 锚定流程

一个使用你自己的 Bitcoin 钱包，把记录的内容哈希写入一笔真实交易的分步流程。每一步都需要你单独点击。

> **这会在 Bitcoin 主网上花费真正的比特币。** 从**创建交易计划**开始，它就在使用你钱包中的真实资金，
> **广播交易**会发送一笔真实交易。没有测试模式。

它所有的全页面板都在**钱包与存档工具 → 区块链锚定**下，即签名记录页面底部收起的面板；每条记录的步骤在各自记录的卡片上。
当某一步需要先观察钱包或资金时，它的链接会为你打开那个面板。

### 你需要准备什么

- 在[网络设置 → 钱包](10-NetworkSettings.md#显示实验性工具)下打开 **Bitcoin 钱包**。
- **UniSat** 浏览器扩展（`window.unisat`）；目前还不支持其他 Bitcoin 钱包。
- 一个在**原生 SegWit** 地址（以 `bc1q…` 开头）上持有可花费比特币的账户。Taproot（`bc1p…`）或传统（`1…`、`3…`）地址上的资金
  可以被观察，但不能签名；审核会报告它无法审核。
- 你的签名记录页面上有一条记录；交易会锚定它的内容哈希。

### 连接钱包

在 **Bitcoin 钱包**卡片上点击**连接 Bitcoin 钱包**，并在扩展中批准连接。ForkBuild 永远看不到你的密钥、助记词或密码；
连接期间，它只获得你的地址、网络和签名能力。

| 状态 | 含义 |
|---|---|
| **已连接** | 显示**账户**和**网络**。 |
| **已断开** | 还没有连接，或者你拒绝了。 |
| **钱包不可用** | 没有扩展、扩展已锁定，或者无法访问。 |

这个连接在整个页面上通用。**断开连接**会断开它，重新加载会忘记它。不在主网上的钱包会被报告为不匹配；
ForkBuild 从不替你切换网络。

### 观察资金

连接后会出现 **Bitcoin 资金**卡片。**观察钱包资金**（然后是**刷新资金**）会读取账户当前可以花费的金额。
它不花费也不预留任何东西，也不会自己刷新。

| 状态 | 含义 |
|---|---|
| **已观察到资金** | UTXO 的数量（**显示资金输入**会列出它们）、总额、脚本类型和找零地址（始终是你自己的账户）。 |
| **不支持的地址格式** | 还不支持计算手续费的地址类型，比如传统的 `3…`。 |
| **资金不可用** | 无法连接资金来源。 |

如果你之后在另一个网络上重新连接，会有一条警告说明这次观察已经过时。

### 构建交易计划

在记录卡片的**去中心化与证据**标签页中，观察过资金后，**Bitcoin 锚定交易 → 创建交易计划**就会启用。
它根据最新的观察来规划，从最大的 UTXO 开始选择，并计算手续费。

| 状态 | 含义 |
|---|---|
| **交易计划已构建** | 网络、内容哈希、输入、手续费、找零、输入总额、完整的输入和输出列表，以及观察资金和构建计划的时间。 |
| **无法构建交易** | 通常是资金不足以支付手续费。 |

新的计划会替换之前审核、签名或广播的任何内容。

### 审核和签名

计划会立即填入**审核 Bitcoin 锚定交易**面板：网络、内容哈希、手续费、找零、输入总额、输入和输出，
以及你钱包的网络是否与这笔交易一致。**签署已审核的交易**（连接了匹配的钱包时启用）会请钱包签名。
ForkBuild 会先检查要签名的内容是否仍然与你审核的完全一致；如果不一致，就不会询问钱包。

| 状态 | 含义 |
|---|---|
| **钱包返回了已签名的 PSBT** | 响应中带有这笔交易的签名材料。它还没有经过验证；那是下一步。 |
| **签名被拒绝** | 你或钱包拒绝了。 |
| **钱包不可用** | 没有连接钱包，或者无法访问。 |
| **签名失败** | 钱包返回了无法使用的东西。 |

### 验证并最终确定

**验证并最终确定交易**会离线地以密码学方式检查签名。

| 状态 | 含义 |
|---|---|
| **交易已最终确定** | 签名有效。显示交易 ID，以及**原始交易字节**下的已最终确定交易。 |
| **签名未通过验证** | 密钥错误、签名错误，或者签名的数据不对。 |
| **最终确定失败** | 其他无法使用的结果。 |

只有原生 SegWit（P2WPKH）输入可以最终确定。最终确定还会记录一条 [Bitcoin 锚定记录](#bitcoin-锚定记录)。

### 广播

**广播交易**会把已最终确定的字节原封不动地发送到 Bitcoin 网络。

| 状态 | 含义 |
|---|---|
| **交易已广播** | 已被网络接受，但还没有打包进区块。 |
| **交易被拒绝** | 被拒绝了。 |
| **无法广播** | 无法连接网络。 |

**再次广播**会重新发送相同的字节。不会自动重试任何东西。

### 观察确认

广播后，**观察确认**会检查它是否已被打包进区块，结果与 [Bitcoin 锚定对账](#bitcoin-锚定对账)相同，有三种。
每次检查都会加入这次广播的**显示确认历史**。这个列表在重新加载后会被清空，但每个结果也都会保存在
[记录观察存档](12-ArchiveAndAchievements.md#记录观察存档)中。

### 这个流程不做什么

一旦**广播交易**成功，这笔交易就会作为一个新锚定加入记录的**外部证据**列表，在你点击**验证证据**之前处于未验证状态；
对等节点可以用**从对等节点发现**找到它。被拒绝或无法连接的广播不会添加任何东西。这个流程不保留它的界面：
新的计划、新的签名或重新加载都会清除审核、签名和广播界面。保留下来的是最终确定时生成的记录，以及观察存档中的每一个广播和确认结果。

### Bitcoin 锚定记录

**Bitcoin 锚定记录**卡片列出此设备最终确定的每笔交易的记录：`{ 锚定 ID、内容哈希、txid、网络、创建时间 }`。
它在**验证并最终确定交易**成功时生成，无论之后广播是否成功，它本身都没有已确认或有效的状态。**显示记录**会列出它们。每一行都有：

- **查看观察**——存档中针对该锚定 ID 持有的每一种广播、确认、内容证明、链上位置和一致性事实的计数。
- **显示记录生命周期**——按时间顺序排列的同样事实，从**已创建记录**开始。没有任何记录的步骤直接不显示。
  打开它不会联系任何网络。

## Base 锚定流程

在 **Base**（一个兼容以太坊的网络）上的同样思路。它与 Bitcoin 相互独立：有自己的钱包、自己的交易
（一笔以数据形式携带内容哈希的自转账），以及自己的术语。

> **这会在 Base 主网上花费真实资金，或者在 Base Sepolia 上花费测试资金——取决于你的钱包在哪个网络上。**
> ForkBuild 从不替你选择网络。

### 你需要准备什么

- 在[网络设置 → 钱包](10-NetworkSettings.md#显示实验性工具)下打开 **Base 钱包**。
- 一个使用标准 [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193) `window.ethereum` 接口的浏览器钱包，
  比如 Coinbase Wallet 或 MetaMask。
- 一个在链 ID **8453**（Base 主网）或 **84532**（Base Sepolia）上的账户。其他任何链都会被报告为不匹配。
- 你的签名记录页面上有一条记录。

### 连接钱包并观察账户

在 **Base 网络**卡片（在**钱包与存档工具 → 区块链锚定**下）上，点击**连接 Base 钱包**并批准。
状态有**已连接**、**已断开**和**钱包不可用**，与 Bitcoin 相同；**断开连接**会断开它，重新加载会忘记它。

然后**观察 Base 账户**（之后是**刷新观察**）会读取账户的链和余额：

| 标记 | 含义 |
|---|---|
| **已观察到 Base 账户** | **网络**、**链 ID**、**账户**、**原生余额**（以 wei 为单位）以及观察时间。 |
| **已连接的网络不是 Base** | 显示实际找到的链 ID。 |
| **Base 账户不可用** | 无法访问钱包。 |

### 构建交易计划

在记录卡片的**去中心化与证据**标签页中，**Base 锚定交易 → 创建 Base 交易计划**（观察过账户后启用）
会构建一笔从你的账户到它自己的未签名自转账，以它的数据携带内容哈希。

| 状态 | 含义 |
|---|---|
| **交易计划已构建** | 网络、链 ID、内容哈希、发送方/接收方（同一个地址）、金额、nonce、gas 上限、最高费用和优先费（以 wei 为单位）、数据，以及观察账户和构建计划的时间。 |
| **Base 网络不可用** | 无法读取账户、费用或 nonce。 |
| **无法构建交易** | 其他失败。 |

新的计划会替换之前审核、签名或广播的任何内容。

### 审核和签名

计划会立即填入卡片的 **Base 交易审核**：发送方、接收方、金额、nonce、gas 数字、内容哈希和交易数据。
**签署已审核的交易**会请钱包签署完全相同的计划。

| 状态 | 含义 |
|---|---|
| **钱包返回了已签名的交易** | 已签名，但还没有经过验证。 |
| **签名被拒绝** | 你或钱包拒绝了。 |
| **钱包不可用** | 没有连接钱包，或者无法访问。 |
| **签名失败** | 钱包返回了无法使用的东西。 |

### 一步创建 Base 锚定

在同一张审核卡片中，**创建 Base 锚定**会一次点击完成已审核交易的签名、最终确定和广播，然后把它加入记录的证据列表。
它可以替代分步按钮，后者仍然可用。

| 标记 | 含义 |
|---|---|
| **已创建锚定** | 已广播；新的锚定会以展开状态出现在[证据列表](#证据列表)中。 |
| **记录被拒绝** | 签名、最终确定或广播被拒绝了。 |
| **没有创建锚定** | 无法访问钱包或网络。 |

之后按钮会变成**再创建一个 Base 锚定**。它会使用你的钱包，并发送一笔真实交易。

### 验证、最终确定和广播

**验证并最终确定交易**会离线地对照已审核的计划检查签名，并恢复出签名者。

| 状态 | 含义 |
|---|---|
| **交易已最终确定** | 有效；显示恢复出的签名者和交易哈希。 |
| **签名未通过验证** | 密钥错误、签名错误，或者数据不对。 |
| **无法最终确定** / **最终确定失败** | 无法检查，或其他无法使用的结果。 |

最终确定会记录一条 [Base 锚定记录](#base-锚定记录)。然后**广播交易**会发送它：**交易已广播**（附带**交易 ID**；尚未打包进区块）、
**交易被拒绝**或**无法广播**。**再次广播**会重新发送相同的字节。

### 观察打包

广播后，**Base 交易打包**部分的**观察交易**会检查它是否已在区块中：

| 标记 | 含义 |
|---|---|
| **交易已打包** | Base 报告了收据：区块哈希、区块号、交易索引、确认数。链重组仍有可能，并且不会被检测到。 |
| **交易未打包** | 还没有收据（待处理和从未发送不作区分）。 |
| **无法获取打包状态** | 无法检查。 |

**再次观察交易**会加入**显示观察历史**。这个列表在重新加载后会被清空，但每次观察也都会保存在
[记录观察存档](12-ArchiveAndAchievements.md#记录观察存档)中。

### Base 锚定记录

与 Bitcoin 的一样，**Base 锚定记录**卡片为每笔已最终确定的交易保留一条记录：`{ 内容哈希、txid、网络、创建时间 }`。
**显示记录**会列出它们，**显示记录生命周期**会显示**已创建记录**，接着是每一次**打包观察 #N**。
Base 的广播结果不会被保存，所以没有广播条目。

只有**创建 Base 锚定**会添加外部证据条目；分步流程从不添加。

## 快照放置

快照放置是一项常规功能，从在 IPFS、Arweave 或本地创建放置，到**放置与 IPFS**标签页中的列表都是。
只有把 IPFS（远程固定）作为偏好的服务是*实验性*的。

**快照放置**是一份签名声明，说明某个存储后端——**IPFS**、**Arweave** 或此设备自己的**本地**存储——
可以提供某条记录内容哈希对应的字节。它不保证这些字节明天还在。不同后端、不同人的多个放置可以并存；没有哪一个更受偏好。

### 创建放置

在记录卡片的**分发**部分中，**内容**区块为每个后端各提供一张卡片，按钮为**创建本地放置**、**创建 IPFS 放置**
或**创建 Arweave 放置**。当你保存了偏好的存储时，区块会以它对应的一个按钮开头（比如**存储到 IPFS**），
并把这些卡片收在**其他存储选项**下。每个按钮都会把此设备为这条记录持有的字节交给那个后端：

- **已创建放置**——已被接受；下面会出现一个新的签名放置。
- **没有创建放置**——无法连接后端，或者此设备没有这份内容。

然后按钮会变成**再创建一个 … 放置**。创建放置仅仅意味着某个后端刚才接受了这些字节。

- **IPFS** 需要你自己的 IPFS 节点 API，默认位于 `http://127.0.0.1:5001`（在[内容服务](10-NetworkSettings.md#内容服务)下更改）。
  没有运行中的节点时，你会得到**没有创建放置**。
- **Arweave** 需要一个钱包扩展，比如 Wander。

*读取* IPFS 放置不需要节点：**解析快照**和**实体化快照**使用公共网关（见[IPFS 网关](10-NetworkSettings.md#ipfs-网关)），
所以你可以获取别人放置的内容。

### 使用偏好的服务

**内容**区块顶部的**存储到 …**，以及卡片**详情 → 放置与 IPFS**标签页中的**使用偏好的服务**，
会在[内容服务](10-NetworkSettings.md#内容服务)下保存的后端上创建一个放置。保存偏好既不会改变各个明确的按钮，
也不会改变已有的放置。没有保存任何东西时，**内容**区块会显示所有后端，而不是**存储到 …**。
保存了 IPFS（远程固定）时，**存储到 …**会使用[内容服务](10-NetworkSettings.md#内容服务)下设置的服务。

| 标签 | 含义 |
|---|---|
| **已创建放置** | 与点击那个后端的按钮相同。 |
| **没有创建放置** | 没有保存偏好。 |
| **未找到偏好的服务** | 保存的后端没有在此设备上注册，或者它是 IPFS（远程固定）但内容服务下没有设置服务。 |

### 快照放置列表

在卡片的**放置与 IPFS**标签页中，**显示放置**会列出这条记录已知的每一个放置：你做的、对等节点发来的，
以及导入的蓝图包中附带的。

| 字段 | 含义 |
|---|---|
| **定位符** | 后端说在哪里可以找到这些字节。 |
| **放置时间** | 声称的放置时间。 |
| **记录** / **内容哈希** | 这个放置的签名把什么绑定在一起。 |
| **放置者** | 签署它的身份。 |

每个放置最多有三个按钮：

- **查看放置**——放置自己的字段，对于 IPFS 还有一个网关链接。它不联系任何网络。下面的**本地已知信息**显示此设备是如何得知它的
  （*在本地得知*、*通过导入包得知*或*通过对等节点交换得知*），以及**这个副本首次见到**它的时间。
- **解析快照**（然后是**再次解析**）——向后端核实这些字节现在是否可以获取，但不保存它们。
- **实体化快照**（然后是**再次实体化**）——解析，如果成功，就把字节保存到此设备上（见
  [本地快照](09-PublicationsAndEvidence.md#本地快照)）。由你挑选放置；它从不替你尝试另一个。

| 实体化结果 | 含义 |
|---|---|
| **已实体化** | 已获取、相符，并保存在这里。 |
| **已经可用** | 此设备已经有相符的字节。 |
| **目前不可用** | 无法连接后端，或者后端没有这些字节。 |
| **已拒绝** | 字节与放置的哈希不符。 |
| **放置无效** | 记录格式错误，或者不是真正签名的。 |

### 解析结果

| 标记 | 含义 |
|---|---|
| **内容可用** | 后端提供了与内容哈希相符的字节。 |
| **没有配置存储后端** | 此设备没有这种存储类型的后端。 |
| **内容不可用** | 连接到了，但它现在没有这些字节。 |
| **获取到的内容与这个放置不符** | 后端提供了错误的字节。 |
| **放置无效** / **签名无效** | 记录格式错误，或者不是真正签名的。 |

结果在本次访问期间保留在这个页面上，不会被分享。两个人对同一个放置可能得到不同的结果（比如只有一个人运行着 IPFS 节点）。
如果某个放置在本次访问中早些时候解析成功，之后却无法连接，它会注明：“这个快照之前曾成功解析；目前不可用。”
不相符的情况永远不会以这种方式被淡化。

### 放置关系

有多个放置时，**放置关系**卡片会显示有多少个后端和不同的位置，统计每个内容哈希对应的放置数量，
并显示**内容绑定：一致**或**冲突**（附带警告）。它只基于声明，而不基于你是否解析过它们，
而且更大的一组并不会被认为更可能正确。

## IPFS 发布

*实验性。* 卡片**放置与 IPFS**标签页中、快照放置下方的 **IPFS 发布**部分，会把内容上传到你选择的固定服务。
（正如该部分所说：本地 Kubo 节点可以解析和发布，远程网关只能解析，远程固定只能发布。）
与放置不同，结果不是别人可以发现的签名声明：它只是一条某个服务商接受了这些字节的记录。
屏幕上的结果在重新加载后会被清除，但每一次成功的发布和每一次验证也都会保存在
[记录观察存档](12-ArchiveAndAchievements.md#记录观察存档)中。

### 配置远程固定服务商

ForkBuild 不自带任何固定服务商。卡片默认使用[内容服务](10-NetworkSettings.md#内容服务)下设置的服务（如果有的话），
以及你在本次访问中输入的令牌。要使用另一个，请点击**配置远程发布**（之后是**重新配置远程发布**）：

| 字段 | 含义 |
|---|---|
| **端点** | 服务的上传 URL。必填。 |
| **凭据**（可选） | 作为 bearer `Authorization` 标头发送。永远不会再显示；卡片只会显示**已配置**或**未配置**。 |
| **请求字段**（可选） | 文件所用的表单字段。默认为 `file`。 |
| **响应字段**（可选） | 存放 CID 的响应字段。默认为 `cid`。 |

**保存配置**只在本次访问中保留它；它从不被存储，**清除配置**会丢弃它；重新加载会回到已保存的服务。
取消会保留之前的配置。重新配置会从头开始，新服务商下没有任何已发布的内容。

### 发布

**发布到远程 IPFS**（然后是**再次发布**）会对照内容哈希检查此设备上的副本，然后上传它。

| 标记 | 含义 |
|---|---|
| **已发布** | 已被接受；服务商返回了一个 CID。 |
| **发布被拒绝** | 被拒绝了，比如凭据错误、请求格式错误或超出配额。重试前请更改配置。 |
| **无法发布** | 无法连接服务商。请稍后再试。 |
| **发布失败** | 其他任何情况，包括本地完整性检查先失败了。 |

已发布的结果会显示内容哈希、定位符（`ipfs://<cid>`）、端点和时间。一个以你的
[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)命名的标记，比如 **Nostr：已公告**或 **Steem：未公告**，
会说明这次发布是否也为快照发现做了公告，让别人可以像找到本地节点发布那样找到它。**未公告**表示只有公告失败了。

### 验证已发布的内容

发布成功后，**内容获取 → 验证 IPFS 内容**（然后是**再次验证**）会通过你的[IPFS 网关](10-NetworkSettings.md#ipfs-网关)
获取字节，并与记录的哈希进行比较：

| 标记 | 含义 |
|---|---|
| **获取到的内容与记录的内容哈希相符** | 相符。 |
| **获取到的内容与记录的内容哈希不符** | 不相符。 |
| **无法获取内容** | 无法连接网关，或者网关没有它。这不是不相符。 |
| **验证失败** | 其他地方出了问题。 |

### 记录历史

再次发布永远不会覆盖之前的记录。**显示记录历史**会列出每一次发布，最早的排在最前面，附带定位符和时间；
**查看**会显示它的定位符、内容哈希、时间和方式（目前总是**远程固定服务商**）。每个条目都有自己的**验证内容**按钮
和**显示验证历史**，即对那条记录每一次检查的按时间顺序排列的列表。

## Steem

*实验性。* ForkBuild 可以通过 Steem 区块链进行公告、存储和分享。公告（记录、快照和评论的公告）是对每月发现帖的回复，比如
[`@forkbuild/forkbuild-snapshot-2026-09`](https://steemit.com/forkbuild/@forkbuild/forkbuild-snapshot-2026-09)。
读取不需要账户。找到的任何内容都会像来自 Nostr 或 Arweave 的公告一样被验证；投票、收益和声誉不会影响它。
设置在[网络设置 → Steem](10-NetworkSettings.md#steem)下。

### 发布到 Steem

在“分发”对话框中、签名记录页面上，或者在**发表评论**旁边选择 **Steem**，或者在
[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)下把它设为默认。你需要持有你账户**发帖**密钥的 Steem Keychain 扩展，
并在 Steem 设置页面上保存你的账户名。ForkBuild 永远看不到这个密钥。每篇帖子都是对本月发现帖的回复，并拒绝收益，
Keychain 会请你批准。如果本月的帖子还不存在，什么都不会发布，你会收到提示。评论总是先保存在此设备上，
如果缺少账户或 Keychain，它的输入框会发出警告。

### 存储到 Steem

在“分发”对话框中或签名记录页面上选择 **Steem** 作为存储。快照会被压缩，并以回复的形式存储在本月的内容帖下
（比如 `@forkbuild/forkbuild-content-2026-10`），没有固定费用或上传费用。数据放在每篇帖子的元数据中；帖子正文是一行说明。
数据放在正文中的旧帖子仍然可以加载。

- **大小。** 一篇帖子最多能放下约 2,500 块积木。更大的作品是一篇索引帖加上最多 20 篇约 48 KB 的帖子，最多约 30,000 块积木。
  再大的作品会在发帖前被拒绝，并建议使用 IPFS 或 Arweave。
- **批准。** Keychain 会为每篇帖子请求批准，间隔至少 4.5 秒，对话框会显示进度（“正在存储到 Steem：已发帖 3/9”）。
- **资源积分。** 发帖会消耗你账户的资源积分，它会在五天内恢复。如果不够，什么都不会发布，并且会告诉你需要多少。进度会显示消耗的比例。
- **如果中途停止**（你拒绝了、积分用完了或连接断了），会告诉你已经存储了多少篇帖子。用同一个账户再次分发，只会补发缺失的帖子。
  在所有帖子都存储完成之前，不会公告任何东西。

签名声明也可以存储到 Steem：在同一个帖子下再发一篇（再批准一次），两者一起分发时排在快照之后。
它会像来自 Arweave 的签名声明一样被读回并检查签名。

### 分享链接

**在 Steem 上。** 签名声明的帖子会显示你作品的图片、标题、你的名字和描述（完整显示，最多 2,000 个字符，并保留它的
[格式](02-TheEditor.md#作品属性)），以及一个“以 3D 查看”的链接。Keychain 会请你批准为图片签名，图片会上传到 Steemit 的图片服务器，
不消耗资源积分；如果你拒绝或无法生成，帖子会在没有图片的情况下发出。标题或描述中的提及、标签和链接会显示为纯文本，
所以不会通知任何人。任何人点击这个链接，即使以前从未用过 ForkBuild，在 ForkBuild 检查了共享世界的签名以及作品是否与公告相符之后
（如果不符，页面会说明原因），都会来到你作品自己的页面，那里有**编辑副本**以及在世界视图中绕着它走走（见
[链接会打开什么](04-PublishingAndForking.md#链接会打开什么)）。之后作品会保存在他们的浏览器中。
链接需要作品既被存储又被公告，“分发”会同时做到这两点。

**任何地方。** 一旦签名声明被存储到 Steem、Arweave 或 IPFS 上，它下面就会出现**分享…**和**复制链接**：
在世界视图的记录面板中、在“分发”对话框的结果中，以及在签名记录页面上。**分享…**会在可用时打开你设备的分享面板；
**复制链接**会复制链接，链接也会显示出来供手动复制。只要快照也已经分发，这个链接在任何设备上都能打开，
并会把作品显示在你放置它的地方：你签名的放置随快照一起传递，链接会把它带上。地址栏中的 `#/world/…` 地址只在你自己的浏览器中有效。

- **Arweave：** 刚分发后，在上传传到各个网关期间，链接可能需要几分钟才能打开。页面会提供**重试**。
- **你自己节点上的 IPFS：** 只有当你的节点在线并且公共网关可以访问时才能打开。固定服务或 Arweave 能在你的电脑关机时保持它可用。
- 朋友们通过他们自己网络设置中的网关读取。IPFS 网关有最多 30 秒的时间来找到声明。

## Blurt

*实验性。* Blurt 是从 Steem 发展而来的区块链，没有点踩。ForkBuild 可以在上面公告、存储和锚定，所有内容都从**你自己的账户**
作为普通 Blurt 帖子发出，并保留收益：当人们为你作品的帖子点赞时，你会赚到 BLURT。没有 ForkBuild 账户，也没有共享的帖子。
设置在[网络设置 → Blurt](10-NetworkSettings.md#blurt)下。

### 发布到 Blurt

在“分发”对话框中、签名记录页面上、**发表评论**旁边或命名面板中选择 **Blurt**，或者在
[公告 / 发现服务](10-NetworkSettings.md#公告--发现服务)下把它设为默认。你需要持有你账户**发帖**密钥的 Blurt Keychain 扩展
（或 WhaleVault），并在 Blurt 设置页面上保存你的账户名。ForkBuild 永远看不到这个密钥，Keychain 会请你批准每一篇帖子。

- **每个作品一篇帖子。** 一次“分发”会从你的账户发布一篇顶层帖子，带有 `forkbuild` 和 `forkbuild-snapshot` 或
  `forkbuild-publication` 标签，然后是你作品自己的[标签](02-TheEditor.md#作品属性)，并附带你作品的图片、标题、你的名字和描述
  （完整显示，最多 2,000 个字符，并保留它的[格式](02-TheEditor.md#作品属性)），以及一个“以 3D 查看”的链接。
  接下来半小时内的内容（记录的公告、一条评论、一个锚定）会通过编辑加到同一篇帖子中，所以你的关注者看到的是一篇帖子，而不是好几篇。
- **图片需要单独批准。** 对于签名声明，Keychain 会先请你为作品的图片签名，然后再批准帖子。它的第二个窗口可能会在浏览器后面打开；
  ForkBuild 会为每一个等待最多两分钟。图片会上传到 Blurt 的图片服务器，浏览器无法直接访问时会通过 ForkBuild 的会合服务器上传；
  如果无法上传，帖子会在没有图片的情况下发出。
- **帖子之间间隔五分钟。** Blurt 每个账户每五分钟只接受一篇顶层帖子。如果你的账户最近发过一篇（比如从另一个应用发的），
  ForkBuild 会等待，对话框会说明要等多久。
- **费用。** 每笔 Blurt 交易都会收取少量 BLURT 费用，由 Blurt 的见证人设定。如果你的账户付不起，什么都不会发布，你会收到提示。
- **别人通过** Blurt 的搜索索引 Nexus **找到它**，Nexus 会列出 ForkBuild 标签下的每一篇帖子，无论多旧。如果没有 Blurt 节点提供 Nexus，
  ForkBuild 会读取标签（它只列出一周内的帖子），然后读取你账户的历史：一旦某人的 ForkBuild 见过你的一篇帖子，它就会继续读取你之后和之前的帖子。

### 存储到 Blurt

在“分发”对话框中或签名记录页面上选择 **Blurt** 作为存储。作品的存储方式与在 Steem 上相同，以回复的形式放在你作品的帖子下：
一条回复最多约 2,500 块积木，或者最多再加 20 条回复，最多约 30,000 块积木。发帖前，ForkBuild 会计算费用，
如果你的余额不足就会拒绝（“把这个作品存储到 Blurt 约需 0.632 BLURT 费用，而你的账户只有 0.100 BLURT”）。
对话框会显示进度和费用。如果中途停止，用同一个账户再次分发，只会补发缺失的回复。

签名声明也可以存储到 Blurt，作为多一条回复。它的链接与 Steem 的一样：任何人点击“以 3D 查看”，在 ForkBuild 检查之后，
都会来到你作品自己的页面。存储后会出现**分享…**和**复制链接**。
