맨 위 막대의 **네트워크 설정**에는 ForkBuild가 어떤 서버와 통신할지 정하는 모든
페이지의 링크가 있습니다. 대부분은 여기서 아무것도 바꿀 필요가 없습니다: 기본값
그대로 동작합니다. 서버가 멈췄을 때, 직접 서버를 운영할 때, 또는 게시물을 저장하고
공지할 곳을 고를 때 여기로 오세요.

각 서버가 나에 대해 무엇을 알게 되는지는 [개인정보 보호](Privacy.md)를 보세요.

## 모든 페이지의 공통 동작

- **저장한 뒤 새로 고치기.** 변경 사항은 다음에 앱을 불러올 때 적용됩니다(Steem과
  Blurt 계정은 예외). 열려 있는 월드 보기나 에디터는 새로 고칠 때까지 이전 설정을 계속
  씁니다.
- 각 페이지에는 자체 **저장**이 있습니다. 저장에 실패하면 이유를 보여 주고 이전
  설정을 그대로 두며, 성공하면 “저장했습니다.”가 표시됩니다.
- 선택지 목록은 알파벳 순으로 표시됩니다.
- **서버 목록에는 기본값이 있습니다.** Arweave 게이트웨이, IPFS 게이트웨이,
  Bitcoin 엔드포인트, Nostr 릴레이, Steem, Blurt, STUN, 랑데부 페이지는 무료 공개 서버
  여러 개로 시작하므로, 하나가 멈춰도 계속 동작합니다. 페이지에는 “기본 … 사용
  중”인지 “저장한 … 사용 중”인지 표시됩니다. 저장한 것이 없으면 텍스트 상자에
  기본값이 한 줄에 하나씩 들어 있어 바로 편집할 수 있습니다. **저장**은 무언가를
  바꾸기 전까지 비활성화되어 있으므로, 이후 버전의 개선된 기본값을 계속 받습니다.
  **기본값으로 초기화**는 내 목록을 지웁니다.
- **검증은 형식만 확인합니다.** 저장은 올바른 종류의 잘 짜인 URL이 아니면
  거부하지만, 서버가 실제로 동작하는지는 확인하지 않습니다. 잘못된 서버는 나중에
  읽기 실패로 드러납니다.
- **기본값은 제3자 서비스입니다.** 각각은 내 IP 주소와 앱이 요청하는 것을 봅니다.
  게이트웨이로 읽은 콘텐츠는 콘텐츠 해시와 대조하므로, 게이트웨이가 다른 바이트로
  바꿔치기할 수 없습니다.

## 콘텐츠 제공자

**…에 저장**(게시물 **콘텐츠** 블록의 첫 번째 버튼)과 **선호 제공자 사용**이
스냅샷 배치를 만들 저장소를
([선호 제공자 사용하기](11-EvidenceAndStorage.md#선호-제공자-사용하기) 참고) 이
기기에 등록된 백엔드 중에서 고르고 **저장**을 클릭하세요. 모든 게시물은 이미 이
기기에 저장되므로 **로컬**은 제공되지 않습니다.

**IPFS (원격 피닝)**은 항상 제공됩니다. 이것을 고르면 모든 **배포** 대화 상자에서
원격 피닝이 저장소로 미리 선택되며, 엔드포인트와 자격 증명은 여전히 매번
입력합니다. 선호 제공자 버튼은 원격 피닝을 쓸 수 없습니다: 이것을 저장하면
**콘텐츠** 블록에 **…에 저장** 대신 모든 백엔드가 표시되고, **선호 제공자 사용**은
**선호 제공자를 찾을 수 없음**을 보고합니다.

두 번째 섹션인 **IPFS 노드**는 새 IPFS 배치를 보낼 노드를 정합니다. 기본값은
`http://127.0.0.1:5001`의 로컬 Kubo 노드입니다. 다른 노드의 API URL을 입력하고
**저장**하거나, **배포 기본값 사용**으로 되돌리세요. IPFS 콘텐츠 읽기에는 영향을
주지 않으며, 읽기에는 [IPFS 게이트웨이](#ipfs-게이트웨이) 목록을 씁니다.

## 공지 / 발견 제공자

게시물(공유 월드, 설계도 저작자 표시, 장소 이름 클레임), 스냅샷, 댓글을 공지할
기본 위치로 **Arweave**, **Blurt**(실험적), **Nostr**, **Steem**(실험적) 중 하나를 고르세요. 기본값일
뿐입니다: 모든 **배포** 대화 상자, 저장소의 카드별 배포 선택기, **댓글 게시** 옆의
네트워크 선택기가 이것으로 시작하며, 작업 하나에 한해 바꿀 수 있습니다. 다른
사람의 콘텐츠를 찾을 때는 항상 그 모두를 검색합니다.

두 번째 섹션 **댓글**은 댓글만의 기본값을 정합니다. 처음 설정인 **위의
공지 / 발견 제공자와 같음**은 위의 선택을 따릅니다. 대신 네트워크를
고르거나, **로컬 및 피어만**을 골라 댓글이 어떤 네트워크에도 올라가지 않게
할 수 있으며 네트워크 계정이 필요 없습니다. 모든 댓글 양식이 이 선택으로
시작하고, 댓글마다 **댓글 게시** 옆에서 계속 바꿀 수 있습니다.

## 증명 / 앵커링 제공자

*실험적.* **…에 앵커링**(게시물 **증명 / 앵커링** 블록의 첫 번째 버튼)이 외부
증거를 만들 곳을 이 기기에 등록된 **Arweave**, **Bitcoin**, **Blurt**, **Steem** 중에서
고르세요. Base 앵커는 매번 지갑 트랜잭션을 검토하고 서명해야 하므로 Base는 제공되지
않습니다. Bitcoin을 고르면 **…에 앵커링** 버튼이 없습니다: 블록에 모든 옵션이
표시되고 지갑 단계를 안내합니다. 실제 Bitcoin 앵커는
[Bitcoin 앵커 절차](11-EvidenceAndStorage.md#bitcoin-앵커-절차)를 보세요.

## Arweave 게이트웨이

Arweave 콘텐츠를 읽는 게이트웨이로, 한 줄에 `http://` 또는 `https://` URL
하나씩입니다. 기본값은 `https://arweave.net`, `https://ardrive.net`,
`https://permagate.io`입니다.

순서대로 시도합니다: 현재 게이트웨이에 연결할 수 없거나 오류를 돌려줄 때만 다음
게이트웨이로 넘어갑니다. Arweave 콘텐츠는 트랜잭션 id로 주소가 정해지므로, 모든
게이트웨이가 같은 바이트를 돌려줍니다.

이 목록은 탈중앙 출처에서 게시물의 콘텐츠를 가져올 때와 Arweave 스냅샷 배치를
해석하거나 구체화할 때 쓰입니다. 내 콘텐츠를 업로드하는 곳은 바꾸지 않습니다.
Arweave 앵커는 목록의 첫 번째 게이트웨이로 만들고 검증합니다.

## IPFS 게이트웨이

IPFS 콘텐츠를 읽는 게이트웨이로, 한 줄에 URL 하나씩이며 Arweave처럼 순서대로
시도합니다. 기본값은 `https://ipfs.io`, `https://dweb.link`,
`https://4everland.io`, `https://ipfs.filebase.io`입니다.

이 목록은 IPFS 스냅샷 배치를 해석하거나 구체화할 때, **IPFS 콘텐츠 검증**,
그리고 IPFS에 있는 콘텐츠의 공유 링크를 열 때 쓰입니다. 내 콘텐츠를 피닝하는 곳은
바꾸지 않습니다.

`https://ipfs.io`를 비롯한 일부 게이트웨이는 봇 확인 뒤에 있는 일부 사람의 자동
요청을 막습니다. 다른 기본값은 다른 운영자가 운영하므로, 읽기가 그쪽으로
넘어갑니다. 분명히 있는 콘텐츠인데 **검증**이나 **해석**이 “Failed to fetch”로
계속 실패하면, 피닝 제공자의 게이트웨이(예: `https://gateway.pinata.cloud`)를 맨
위에 추가하세요.

## Bitcoin 엔드포인트

*실험적.* Bitcoin 앵커링이 트랜잭션을 브로드캐스트하고, 컨펌을 확인하고, 지갑
자금을 조회하고, 앵커의 OP_RETURN 증명을 검증할 때 쓰는 Esplora 호환 API입니다.
한 줄에 `http://` 또는 `https://` URL 하나씩이며, 기본값은
`https://blockstream.info/api`와 `https://mempool.space/api`입니다.

조회는 처음 응답하는 엔드포인트를 씁니다. 브로드캐스트는 이전 엔드포인트에 연결할
수 없을 때만 다음으로 넘어가며, 한 엔드포인트가 트랜잭션을 거부한 뒤에는 절대
넘어가지 않습니다.

## Nostr 릴레이

ForkBuild가 Nostr로 게시하거나 발견하는 모든 것 — 게시물(공유 월드, 설계도
저작자 표시, 장소 이름 클레임), 스냅샷, 댓글 — 에 쓰는 릴레이입니다. 한 줄에
`ws://` 또는 `wss://` URL 하나씩이며, 기본값은 `wss://relay.damus.io`,
`wss://nos.lol`, `wss://relay.primal.net`입니다. **저장**은 목록 전체를 교체하며,
올바른 URL이 아닌 줄이 있으면 거부합니다.

게이트웨이와 달리 릴레이는 순서대로 시도하지 않습니다: 공지는 모든 릴레이에 동시에
보내고 발견은 모든 릴레이에 묻기 때문에, 릴레이가 하나 더 있을 때마다 다른 릴레이가
멈춰 있어도 더 많은 사람이 내 콘텐츠를 찾을 수 있습니다. 여기에는 릴레이별 상태가
없으며, **배포** 결과에 릴레이마다 **발견** 줄이 하나씩 나열됩니다.

## Steem

*실험적.* **게시** 아래에서 **내 Steem 계정**을 정하세요(새로 고치지 않아도 바로
적용). Steem에 게시하거나 저장하려면 필요합니다 —
[Steem](11-EvidenceAndStorage.md#steem)을 보세요. Steem에서 읽는 데는 계정이 필요
없습니다. 페이지의 나머지는 Steem을 읽는 곳을 정합니다:

- **API 노드**, 한 줄에 `https://` URL 하나씩(기본값 `https://api.steemit.com`과
  `https://api.justyy.com`), 순서대로 시도.
- **스레드 계정**, 한 줄에 하나씩(기본값 `forkbuild`): 누구의 월간 발견 스레드를
  읽을지. 커뮤니티가 자체 스레드를 운영한다면 추가하세요.
- **읽기 시작할 달**(기본값 2026년 9월): ForkBuild는 그달부터 지금까지 매달을
  읽으며, 최근 36개월까지입니다.

연결할 수 있는 Steem 노드가 없으면, **새 댓글 확인**과 스냅샷 발견은 찾은 것이
없다고 보고하는 대신 Steem을 사용할 수 없다고 알려 줍니다.

## Blurt

*실험적.* **게시** 아래에서 **내 Blurt 계정**을 정하세요(새로 고치지 않아도 바로
적용). Blurt에 게시하거나 저장하거나 앵커링하려면 필요합니다 —
[Blurt](11-EvidenceAndStorage.md#blurt)를 보세요. Blurt에서 읽는 데는 계정이
필요 없습니다. 페이지의 나머지는 Blurt를 읽는 곳을 정합니다:

**API 노드**, 한 줄에 `https://` URL 하나(기본값 `https://rpc.blurt.blog`와
`https://rpc.beblurt.com`), 순서대로 시도합니다. ForkBuild는 게시물을 아무리
오래되었어도 모두 보관하는 Blurt의 검색 색인 Nexus로 게시물을 찾으며, Nexus를
제공하지 않는 노드는 건너뜁니다. Nexus를 제공하는 노드가 없으면 Blurt 자체의
태그 목록으로 넘어가는데, 이 목록은 게시물을 보상이 지급되는 7일 뒤까지만
보관하므로, 더 오래된 게시물은 이 기기에서 그 태그로 게시하는 것을 본 계정들의
기록에서 찾습니다.

연결할 수 있는 Blurt 노드가 없으면, **새 댓글 확인**과 스냅샷 발견은 찾은 것이
없다고 보고하는 대신 Blurt를 사용할 수 없다고 알려 줍니다.
