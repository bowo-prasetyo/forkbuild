# 10 — ネットワーク設定

<!-- languages -->
[English](../10-NetworkSettings.md) · [Deutsch](../de/10-NetworkSettings.md) · [Español](../es/10-NetworkSettings.md) · [Bahasa Indonesia](../id/10-NetworkSettings.md) · **日本語** · [Português (Brasil)](../pt-BR/10-NetworkSettings.md)

上部のバーの **ネットワーク設定** には、ForkBuild がどのサーバーと
通信するかを決めるページがすべてまとまっています。ほとんどの人は、
ここで何も変える必要はありません。既定の設定でそのまま動きます。
サーバーが止まっているとき、自分でサーバーを運用するとき、公開物を
どこに保存・告知するかを選ぶときに来てください。

各サーバーがあなたについて何を知るかは、[プライバシー](Privacy.md) を
参照してください。

## ページ一覧

| ページ | ルート | 設定する内容 |

| **告知 / 発見サービス** | `/settings/announcement-discovery-provider` | 告知の既定の送り先: Nostr、Arweave、Steem — [下記](#告知--発見サービス) を参照 |

## すべてのページに共通する動作

- **保存したら再読み込みしてください。** 変更は、次にアプリを読み込んだ
  ときに反映されます（Steem アカウントだけは例外です）。開いている
  ワールドビューやエディターは、再読み込みするまで古い設定を使い続け
  ます。
- 各ページにはそれぞれ **保存** があります。保存に失敗すると理由が
  表示され、以前の設定はそのまま残ります。成功すると「保存しました。」
  と表示されます。
- 選択肢の一覧はアルファベット順に表示されます。
- **サーバーの一覧には既定値があります。** Arweaveゲートウェイ、
  IPFSゲートウェイ、Bitcoinエンドポイント、Nostrリレー、Steem、STUN、
  ランデブーのページには、最初から無料の公開サーバーがいくつか入って
  いるので、1 つが止まっていても動き続けます。ページには「既定の…を
  使用中」か「保存した…を使用中」かが表示されます。何も保存していない
  ときは、テキスト欄に既定値が 1 行に 1 つずつ入っていて、そのまま
  編集できます。何か変更するまで **保存** は押せないので、以降の
  バージョンで改善された既定値を受け取り続けられます。**既定に戻す** で
  自分の一覧を削除します。
- **検証するのは形式だけです。** 保存は、正しい種類の整った URL でない
  ものを拒否しますが、サーバーが動くかどうかは確認しません。間違った
  サーバーは、あとで読み込みの失敗として現れます。
- **既定値は第三者のサービスです。** それぞれのサービスには、あなたの
  IP アドレスと、アプリが何を要求したかが見えます。ゲートウェイを
  通して読んだコンテンツはコンテンツのハッシュと照合されるので、
  ゲートウェイが別のバイト列にすり替えることはできません。

## コンテンツサービス

**…に保存**（公開物の **内容** ブロックの最初のボタン）と
**優先するサービスを使う** がスナップショットの配置を作成するストレージを
（[優先するサービスを使う](11-EvidenceAndStorage.md#優先するサービスを使う) を参照）、
このデバイスに登録されているバックエンドから選び、**保存** をクリック
します。すべての公開物はすでにこのデバイスに保存されているので、
**ローカル** は選択肢にありません。

**IPFS（リモートピン留め）** は常に選択肢にあります。これを選ぶと、
すべての **配信** ダイアログでリモートピン留めがストレージとして最初
から選ばれます。エンドポイントと認証情報は毎回入力します。優先する
サービスのボタンはリモートピン留めを使えません。これを保存していると、
**内容** ブロックには **…に保存** の代わりにすべてのバックエンドが
表示され、**優先するサービスを使う** は
**優先するサービスが見つかりません** と報告します。

2 つ目のセクションの **IPFSノード** では、新しい IPFS の配置の送り先
ノードを設定します。既定は `http://127.0.0.1:5001` のローカルの Kubo
ノードです。別のノードの API の URL を入力して **保存** するか、
**デプロイの既定値を使う** で元に戻します。IPFS のコンテンツの読み込みは
[IPFSゲートウェイ](#ipfsゲートウェイ) の一覧を使うので、この設定の
影響を受けません。

## 告知 / 発見サービス

公開物（共有ワールド、ブループリントの作者情報、地名のクレーム）、
スナップショット、コメントを告知する既定の場所として、**Arweave**、
**Nostr**、**Steem**（試験的）のいずれかを選びます。これは既定値に
すぎません。すべての **配信** ダイアログ、リポジトリのカードごとの
配信の選択、**コメントを投稿** の横のネットワークの選択は、最初はこれに
なっていて、1 回の操作に限って切り替えられます。
他の人のコンテンツを見つけるときは、常に 3 つすべてを検索します。

## 証明 / アンカリングサービス

*試験的。* **…にアンカー**（公開物の **証明 / アンカリング** ブロックの
最初のボタン）が外部証拠を作る場所を、このデバイスに登録されている
**Arweave**、**Bitcoin**、**Steem** から選びます。Base のアンカーには
必ずウォレットのトランザクションを確認して署名する必要があるので、Base は
選択肢に出ません。Bitcoin を選ぶと **…にアンカー** ボタンはなく、
ブロックにはすべての選択肢が表示され、ウォレットの手順が案内されます。
実際の Bitcoin のアンカーについては
[Bitcoin のアンカーパイプライン](11-EvidenceAndStorage.md#bitcoin-のアンカーパイプライン)
を参照してください。

## Arweaveゲートウェイ

Arweave のコンテンツを読むためのゲートウェイで、`http://` または
`https://` の URL を 1 行に 1 つ書きます。既定は `https://arweave.net`、
`https://ardrive.net`、`https://permagate.io` です。

ゲートウェイは順番に試されます。今のゲートウェイに到達できないか、
エラーを返したときだけ、次のゲートウェイに移ります。Arweave の
コンテンツはトランザクション ID で指定されるので、どのゲートウェイも
同じバイト列を返します。

この一覧は、分散型の情報源から公開物の素材を取得するときと、Arweave の
スナップショットの配置を解決・具現化するときに使われます。自分の
コンテンツのアップロード先は変わりません。Arweave のアンカーは、作成と
検証に一覧の最初のゲートウェイを使います。

## IPFSゲートウェイ

IPFS のコンテンツを読むためのゲートウェイで、URL を 1 行に 1 つ書き、
Arweave と同じように順番に試されます。既定は `https://ipfs.io`、
`https://dweb.link`、`https://4everland.io`、`https://ipfs.filebase.io`
です。

この一覧は、IPFS のスナップショットの配置を解決・具現化するとき、
**IPFSの内容を検証** のとき、IPFS 上のコンテンツへの共有リンクを開く
ときに使われます。自分のコンテンツのピン留め先は変わりません。

`https://ipfs.io` など一部のゲートウェイは、ボット対策の確認の向こうに
いる一部の人からの自動リクエストをブロックします。ほかの既定の
ゲートウェイは別の運営者が運用しているので、読み込みはそちらに回ります。
存在するとわかっているコンテンツで **検証** や **解決** が
「Failed to fetch」で失敗し続ける場合は、使っているピン留めサービスの
ゲートウェイ（たとえば `https://gateway.pinata.cloud`）を一番上に
追加してください。

## Bitcoinエンドポイント

*試験的。* Bitcoin のアンカリングが、トランザクションのブロードキャスト、
承認の確認、ウォレットの資金の照会、アンカーの OP_RETURN 証明の検証に
使う、Esplora 互換の API です。`http://` または `https://` の URL を
1 行に 1 つ書きます。既定は `https://blockstream.info/api` と
`https://mempool.space/api` です。

照会には最初に応答したエンドポイントが使われます。ブロードキャストが
次のエンドポイントに移るのは、前のエンドポイントに到達できなかった
ときだけで、トランザクションを拒否されたあとに移ることはありません。

## Nostrリレー

ForkBuild が Nostr で公開・発見するすべてのもの、つまり公開物（共有
ワールド、ブループリントの作者情報、地名のクレーム）、スナップショット、
コメントに使うリレーです。`ws://` または `wss://` の URL を 1 行に 1 つ
書きます。既定は `wss://relay.damus.io`、`wss://nos.lol`、
`wss://relay.primal.net` です。**保存** は一覧全体を置き換え、有効な
URL でない行が 1 つでもあれば拒否します。

ゲートウェイと違い、リレーは順番には試されません。告知はすべての
リレーに同時に送られ、発見はすべてのリレーに問い合わせるので、リレーを
増やすほど、ほかのリレーが止まっているときでも、より多くの人に
コンテンツを見つけてもらえます。ここにはリレーごとの状態は表示され
ません。**配信** の結果に、リレーごとに 1 行ずつ **発見** の行が表示
されます。

## Steem

*試験的。* **投稿** の下で **あなたのSteemアカウント** を設定します
（再読み込みなしですぐに反映されます）。Steem に投稿したり保存したり
するのに必要です — [Steem](11-EvidenceAndStorage.md#steem) を参照して
ください。Steem から読むだけならアカウントは不要です。ページの残りの
部分では、Steem をどこから読むかを設定します。

- **APIノード** — `https://` の URL を 1 行に 1 つ（既定は
  `https://api.steemit.com` と `https://api.justyy.com`）。順番に試され
  ます。
- **スレッドのアカウント** — 1 行に 1 つ（既定は `forkbuild`）。誰の
  毎月の発見用スレッドを読むかです。コミュニティが独自のスレッドを
  運営している場合は追加してください。
- **読み始める月**（既定は 2026 年 9 月） — ForkBuild はそこから現在
  まで、最大で直近 36 か月分のすべての月を読みます。

どの Steem ノードにも到達できないときは、**新しいコメントを確認** と
スナップショットの発見は、何も見つからなかったと報告するのではなく、
Steem が利用できないことを示します。
