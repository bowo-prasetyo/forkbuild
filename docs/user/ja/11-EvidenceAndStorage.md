# 11 — 証拠とストレージ

<!-- languages -->
[English](../11-EvidenceAndStorage.md) · [Deutsch](../de/11-EvidenceAndStorage.md) · [Español](../es/11-EvidenceAndStorage.md) · [Français](../fr/11-EvidenceAndStorage.md) · [Bahasa Indonesia](../id/11-EvidenceAndStorage.md) · **日本語** · [한국어](../ko/11-EvidenceAndStorage.md) · [Português (Brasil)](../pt-BR/11-EvidenceAndStorage.md)
<!-- /languages -->

> **ほとんどが試験的です。** カードの **配信 → 内容** ブロックから
> IPFS や Arweave にコンテンツを保存すること（[配置を作成する](#配置を作成する)
> と [優先するサービスを使う](#優先するサービスを使う)）は通常の機能
> です。ここにあるほかのものはすべて **実験的** です。外部の証拠と 2 つの
> ウォレットのパイプライン、スナップショットの配置の一覧、リモート IPFS
> ピン留め、Steem です。今後のバージョンで変わったり削除されたりする
> ことがあり、作ったものが引き継がれないこともあります。ページでは
> これらの部分に **実験的** のバッジを付けています。

**公開物** ページ（[公開物と外部証拠](09-PublicationsAndEvidence.md) を
参照）のどのカードにも、公開物が *いつ* 存在したかを証明するための
セクションと、その内容をほかの人が取得できる場所に置くためのセクションが
あります。

- **[外部の証拠](#外部の証拠)** — 公開物の内容のハッシュがある時点に
  存在していたという、Bitcoin、Base、Arweave、Steem、Blurt 上の記録。
- **[Bitcoin のアンカーパイプライン](#bitcoin-のアンカーパイプライン)**
  と **[Base のアンカーパイプライン](#base-のアンカーパイプライン)** —
  自分のウォレットを使って実際のトランザクションを書き込む、段階的な
  流れ。
- **[スナップショットの配置](#スナップショットの配置)** — 内容をどこで
  取得できるか（IPFS、Arweave、このデバイス）を示す署名付きのポインター。
- **[IPFSへの公開](#ipfsへの公開)** — リモートのピン留めサービスへの
  アップロード。
- **[Steem](#steem)** — Steem への投稿、保存、リンクの共有。
- **[Blurt](#blurt)** — 自分のアカウントからの、報酬付きの Blurt への
  投稿、保存、アンカー。

証拠と配置は、違う問いに答えます。アンカーは、ハッシュがある時点で
記録されたことを示しますが、そのバイト列を今も取得できるかについては
何も言いません。配置は、バイト列をどこで取得できるかを示しますが、
クレームが最初にいつ作られたかについては何も言いません。

## 外部の証拠

*実験的。*

ここに一覧表示されるアンカーは、「これは外部で記録された」という、
正しく署名された記録をこのデバイスが持っている、という意味でしかあり
ません。記録が本当に行われたかは、**証拠を検証** をクリックしたときに
だけ確認されます。ページ上で自動で検証されるものはありません。読み込み
時も、証拠が届いたときも、一覧を開いたときもです。

### 証拠を作る

公開物のカードの **配信** セクションにある **証明 / アンカリング**
ブロック（**実験的** と表示）には、1 回のクリックで作れる証拠の種類
ごとに、それぞれのボタン付きのカードがあります。**Arweaveアンカーを
作成** と **Steemアンカーを作成** です。Bitcoin と Base のアンカーには
このカードはありません。カードの **詳細 → 分散化と証拠** タブで、
それぞれのウォレットの手順を通して作り、ブロックにもそう書かれて
います。優先するサービスを保存していると、これらのカードは、その
サービス専用のボタンの下の **他のアンカリングの選択肢** に折りたたまれ
ます（[優先するサービスでアンカーする](#優先するサービスでアンカーする)
を参照）。どれも、公開物の内容のハッシュをそのネットワークの
トランザクションに記録し、結果は次の 3 つのどれかです。

| 結果 | 意味 |
|---|---|
| **アンカーを作成しました** | うまくいきました。新しいアンカーが一覧に、未検証の状態で表示されます。 |
| **記録が拒否されました** | ネットワークには届きましたが、拒否されました。 |
| **アンカーは作成されませんでした** | ネットワークに届かなかったか、このデバイスがそのネットワーク用に署名できません。 |

- Bitcoin では [Bitcoin のアンカーパイプライン](#bitcoin-のアンカーパイプライン)
  を、Base では [1 回で Base のアンカーを作る](#1-回で-base-のアンカーを作る)
  を使います。
- **Arweaveアンカーを作成** には、Wander などの Arweave のウォレット
  拡張機能が必要です。
- **Steemアンカーを作成** には、Steem Keychain 拡張機能と、
  [ネットワーク設定 → Steem](10-NetworkSettings.md#steem) で設定した
  Steem アカウントが必要です。
- **Blurtアンカーを作成** には、Blurt Keychain 拡張機能（または
  WhaleVault）と、[ネットワーク設定 → Blurt](10-NetworkSettings.md#blurt)
  で設定した Blurt アカウントが必要です。

内容のハッシュが SHA-256 になる前に作られた公開物は、これらのボタン
でも、Bitcoin や Base の手順でも、**複数の公開物をアンカー** でも、
決してアンカーされません。ほかの誰も古いハッシュで内容を確認できない
ので、その記録は何も証明しないからです。ウォレットに尋ねる前に、
**記録が拒否されました**（Bitcoin と Base では、トランザクションの手順の
失敗）として、もう一度公開するよう表示されます。配置も同じで、
**配置は作成されませんでした** で終わります。

成功すると、ボタンは **…アンカーをもう1つ作成** になり、2 つ目の
独立したアンカーを作ります。Base のアンカーは作り方が違います。
[1 回で Base のアンカーを作る](#1-回で-base-のアンカーを作る) を参照
してください。

**Steem のアンカーは Bitcoin のものより弱い証拠です。** 手数料は
かからず、リソースクレジット（回復します）を使うだけで、ブロックは
約 1 分後に確定します。それまでカードには **Waiting for finality**
（確定待ち）と表示され、次に **Anchored**（アンカー済み）になります
（まれにチェーンがそれを捨てた場合は **Not anchored**（未アンカー）に
なるので、作り直してください）。**証拠を検証** は、最初の 1 分間は
**検証を利用できません** と報告し、その後は、いつ、どのウィットネスに
よってブロックが記録されたかを示します。**証拠を調べる** は、デバイスが
オフラインで確認した、署名済みのブロックヘッダーのコピーから、ブロックの
時刻をすぐに表示します。Steem のブロックは、プルーフ・オブ・ワークでは
なく、ステークで選ばれた約 21 のウィットネスが署名するので、十分な数が
結託すれば履歴を書き換えられます。カードには「Steem のウィットネスに
よる証明」と表示されます。Steem のアンカーは、Bitcoin のアンカーの
代わりではなく、それと並べる手軽で無料の証拠として使ってください。

**Blurt のアンカー** も同じように Blurt のウィットネスが証明するもので、
やはり Bitcoin のものより弱い証拠です。このデバイスがすでに作品の
スナップショットを Blurt に投稿している（告知した、またはそこに保存した）
場合は、その投稿がアンカーになります。**Blurtアンカーを作成** は何も
投稿せず、費用もかかりません。そうでない場合は、作品の内容のハッシュを
現在の Blurt 投稿に追加するか、新しい投稿を作り、少額の BLURT 手数料が
かかります。確定、**証拠を検証**、**証拠を調べる** は Steem と同じように
動き、カードにはその投稿へのリンクが表示されます。

**Steem で複数の公開物をまとめてアンカーする。**
**ウォレット・アーカイブ・公開者向けツール → ブロックチェーンへの
アンカリング** の **複数の公開物をSteemにアンカー** に、目録に入って
いる公開物が並びます。必要なものにチェックを入れて（または
**未アンカーのものを選択**）、**N件の公開物をSteemにアンカー** を
クリックします。Keychain で 1 回承認すると、最大 64 件をアンカーします。
各公開物には、それぞれ独立に検証される独自のアンカーができます。
**複数の公開物をBlurtにアンカー** も同じように動き、Blurt Keychain で
1 回承認します。

### 優先するサービスでアンカーする

**証明 / アンカリング** ブロックの **設定** リンクは
[証明 / アンカリングサービス](10-NetworkSettings.md#証明--アンカリングサービス)
を開き、そこで既定を選びます。選ぶと、ブロックの先頭に、そのサービスの
名前の付いたボタン（**Steemにアンカー** など）が 1 つ表示され、上の
ボタンと同じ結果でそこにアンカーします。動作中は **アンカー中…** と
表示され、終わると新しいアンカーのトランザクションと内容のハッシュが
表示されます。ほかの種類は、**他のアンカリングの選択肢** の下で、
いつでも 1 クリックで使えます。優先するサービスを保存しても、それらの
ボタンや既存のアンカーは変わりません。

何も保存していないとき、保存したサービスがこのデバイスに登録されて
いないとき、またはそれが Bitcoin のときは、このボタンはなく、すべての
選択肢が表示されます。Bitcoin のアンカーはウォレットの手順で作る
もの（[Bitcoin のアンカーパイプライン](#bitcoin-のアンカーパイプライン)
を参照）で、ブロックにもそう書かれています。

### ピアから発見

接続中のピアが渡してくれるのは、接続している間に作られたか、
告知し直された証拠だけです。**ピアから発見** はその隙間を埋めます。
接続中の各ピアに 1 人ずつ、この公開物について知っているすべての
アンカー（ほかの人から知ったものも含む）を尋ねます。ページのほかの
ものがピアに連絡することはありません。

| メッセージ | 意味 |
|---|---|
| *ピアから新しい証拠の主張がN件見つかりました。* | 下の一覧に追加されました。 |
| *ピアから新しい証拠の主張は見つかりませんでした。* | これらのピアには新しいものがありませんでした。証拠が存在しないという意味ではありません。 |
| *問い合わせできる認証済みのピアがいませんでした。* | 先にピアと接続してください（[ピア接続と友達](07-PeerConnectionsAndFriends.md) を参照）。 |
| *要求したピアの発見処理を完了できませんでした。* | ピアに尋ねる前に、ローカルで何かが失敗しました。 |

発見したアンカーは未検証の状態で届き、以前の検証結果は残り、同じ
アンカーが 2 回追加されることはありません。

### 証拠の一覧

カードの **分散化と証拠** タブの **外部の証拠** には、知られている
アンカーの数と **ピアから発見**（上記）があります。**証拠を表示** は、
その公開物について知られているすべてのアンカーを、食い違うものも含めて
並べて表示します。アンカーが 2 つ以上あると、まず **内容の結び付け**
の概要が表示され、内容のハッシュごとのアンカーの数を数え、違うハッシュを
主張しているときは警告します。どれが正しいかは示しません。

各アンカーには次のものが表示されます。

| 項目 | 意味 |
|---|---|
| **ロケーター** | 外部のシステムが示す、記録の場所。 |
| **記録日時** | 主張されている記録の時刻（検証するまでは主張にすぎません）。 |
| **公開物 / コンテンツハッシュ** | このアンカーの署名が結び付けているもの。 |
| **証明者** | アンカーに署名したアイデンティティ。 |

- **証拠を検証**（その後は **もう一度検証**）は、今すぐ外部のシステムに
  確認します。[検証の結果](#検証の結果) を参照してください。
- **証拠を調べる** は、生のクレームを表示します。正確な時刻、ロケーター、
  Bitcoin ではブロックエクスプローラーへのリンクと生の証明です。
  デバイスにあるものだけを読みます。一番下の **ローカルの知識** には、
  このデバイスがそのアンカーをどう知ったか（**取得**: *ローカルで把握*、
  *パッケージのインポートで把握*、*ピアとの交換で把握*）と
  **このレプリカでの初回確認** が表示されます。ピアの名前は示さず、
  信頼の目安でもありません。

### 検証の結果

| ラベル | 意味 |
|---|---|
| **独立して検証済み** | 外部のシステムが、主張されたとおりであることを確認しました。 |
| **証明は独立して検証されていません** | 本当に署名されていますが、このデバイスはこの種類のアンカーを外部で確認できません。 |
| **検証を利用できません** | 外部のシステムに届きませんでした。無効という意味ではありません。 |
| **無効な証拠** / **無効な署名** | 記録の形式が正しくないか、本当に署名されたものではありません。 |
| **内容の不一致** | アンカーがこの公開物と一致しません。 |
| **無効な外部の証明** | 外部のシステムが、クレームは偽りだと示しています。 |

この訪問の中でアンカーを以前に検証していて、あとの確認でネットワークに
届かなかった場合は、「この証拠は以前に独立して検証されましたが、現在は
検証を利用できません。」という注記が残ります。

Base のアンカーは、ここで作ったものも受け取ったものも、同じ
**証拠を検証** ボタンで検証します。

### Bitcoin アンカーの照合

Bitcoin のアンカーのカードには **Bitcoinアンカー** のセクションもあり
ます。**照合**（その後は **もう一度照合**）は、2 つの別々の問いを尋ね、
両方の答えを表示します。

| 承認 | 意味 |
|---|---|
| **トランザクションは承認されました** | マイニングされました。ブロックの高さ、ブロックのハッシュ、承認数を表示します。 |
| **トランザクションは承認されていません** | 見つからないか、まだマイニングされていません（この 2 つは区別されません）。 |
| **承認の状態を利用できません** | 確認できませんでした。 |

| 内容の証明 | 意味 |
|---|---|
| **ハッシュはOP_RETURNと一致しています** | トランザクションが、主張された内容のハッシュを持っています。 |
| **ハッシュがOP_RETURNと一致しません** | 持っていないか、証明の形式が正しくありません。 |
| **内容の証明を利用できません** | 確認できませんでした。 |

承認されたトランザクションでも OP_RETURN が一致しない場合は、そのとおり
に表示されます。照合のたびの承認の結果は、**承認の履歴を表示** に古い
順に追加されます。内容の証明は最新の結果だけを表示します。

## Bitcoin のアンカーパイプライン

自分の Bitcoin ウォレットを使って、公開物の内容のハッシュを実際の
トランザクションに書き込む、段階的な流れです。各段階はそれぞれ別の
クリックです。

> **これは Bitcoin メインネットで本物のビットコインを使います。**
> **トランザクション計画を作成** 以降は、ウォレットの本物の資金を扱い、
> **トランザクションをブロードキャスト** は本物のトランザクションを
> 送ります。テストモードはありません。

ページ全体のパネルはすべて、公開物ページの一番下に折りたたまれた
**ウォレット・アーカイブ・公開者向けツール → ブロックチェーンへの
アンカリング** にあります。公開物ごとの手順は、各公開物のカードに
あります。先にウォレットや資金を観測する必要がある手順では、その
リンクからパネルが自動で開きます。

### 必要なもの

- **UniSat** ブラウザー拡張機能（`window.unisat`）。ほかの Bitcoin
  ウォレットにはまだ対応していません。
- **ネイティブ SegWit** のアドレス（`bc1q…` で始まる）に使えるビット
  コインがあるアカウント。Taproot（`bc1p…`）や従来型（`1…`、`3…`）の
  アドレスの資金は、観測はできますが署名はできず、確認の段階で確認
  できないと報告されます。
- 公開物ページにある公開物。トランザクションは、その内容のハッシュを
  アンカーします。

### ウォレットを接続する

**Bitcoinウォレット** カードの **Bitcoinウォレットを接続** をクリックし、
拡張機能で接続を承認します。ForkBuild があなたの鍵、シードフレーズ、
パスワードを見ることはありません。接続している間、アドレス、
ネットワーク、署名する機能を受け取ります。

| 状態 | 意味 |
|---|---|
| **接続中** | **アカウント** と **ネットワーク** を表示します。 |
| **未接続** | まだ接続していないか、あなたが断りました。 |
| **ウォレットを利用できません** | 拡張機能がないか、ロックされているか、届きません。 |

接続はページ全体で使われます。**切断** で切り、再読み込みすると忘れ
ます。メインネット以外のネットワークにあるウォレットは不一致として
報告されます。ForkBuild がネットワークを切り替えることはありません。

### 資金を観測する

接続すると **Bitcoinの資金** カードが表示されます。
**ウォレットの資金を観測**（その後は **資金を更新**）は、そのアカウントが
今使えるものを読みます。何も使わず、何も確保せず、自動で更新もしません。

| 状態 | 意味 |
|---|---|
| **資金を観測しました** | UTXO の数（**資金の入力を表示** で一覧表示）、その合計、スクリプトの種類、おつりのアドレス（常に自分のアカウント）。 |
| **対応していないアドレス形式です** | 従来型の `3…` など、まだ手数料に対応していないアドレスの種類です。 |
| **資金を利用できません** | 資金の情報源に届きませんでした。 |

あとで別のネットワークで接続し直すと、観測が古くなっていることを
警告します。

### トランザクション計画を作る

公開物のカードの **分散化と証拠** タブにある **Bitcoinアンカーの
トランザクション → トランザクション計画を作成** は、資金を観測すると
使えるようになります。最新の観測に基づいて、大きい UTXO から順に選び、
手数料を計算します。

| 状態 | 意味 |
|---|---|
| **トランザクション計画を作成しました** | ネットワーク、内容のハッシュ、入力、手数料、おつり、入力の合計、すべての入力と出力の一覧、資金を観測した時刻と計画を作った時刻。 |
| **トランザクションを作成できません** | たいていは、資金で手数料をまかなえません。 |

新しい計画は、それ以前に確認、署名、ブロードキャストしたものを置き換え
ます。

### 確認して署名する

計画ができると、すぐに **Bitcoinアンカーのトランザクションを確認** の
パネルが埋まります。ネットワーク、内容のハッシュ、手数料、おつり、
入力の合計、入力と出力、そしてウォレットのネットワークがこの
トランザクションと一致しているかです。**確認したトランザクションに
署名**（一致するウォレットが接続されていると使えます）は、ウォレットに
署名を求めます。ForkBuild はまず、署名しようとしているものが、あなたが
確認したものとまったく同じであることを確かめます。違っていれば、
ウォレットには尋ねません。

| 状態 | 意味 |
|---|---|
| **ウォレットが署名済みのPSBTを返しました** | 応答に、このトランザクションの署名の材料が含まれています。まだ検証されていません。それは次の段階です。 |
| **署名が拒否されました** | あなたかウォレットが断りました。 |
| **ウォレットを利用できません** | ウォレットが接続されていないか、届きません。 |
| **署名に失敗しました** | ウォレットが使えないものを返しました。 |

### 検証して確定する

**トランザクションを検証して確定** は、署名をオフラインで暗号学的に
確認します。

| 状態 | 意味 |
|---|---|
| **トランザクションを確定しました** | 署名は有効です。トランザクション ID と、**生のトランザクションのバイト列** の下に確定したトランザクションを表示します。 |
| **署名を検証できませんでした** | 鍵が違うか、署名が違うか、違うデータに署名しています。 |
| **確定に失敗しました** | そのほかの使えない結果です。 |

確定できるのは、ネイティブ SegWit（P2WPKH）の入力だけです。確定すると
[Bitcoin アンカーの公開](#bitcoin-アンカーの公開) の記録も作られます。

### ブロードキャストする

**トランザクションをブロードキャスト** は、確定したバイト列をそのまま
Bitcoin ネットワークに送ります。

| 状態 | 意味 |
|---|---|
| **トランザクションをブロードキャストしました** | ネットワークに受け入れられましたが、まだマイニングされていません。 |
| **トランザクションが拒否されました** | 拒否されました。 |
| **ブロードキャストを利用できません** | ネットワークに届きませんでした。 |

**もう一度ブロードキャスト** は同じバイト列を送り直します。自動で
再試行されるものはありません。

### 承認を観測する

ブロードキャストしたあと、**承認を観測** はそれがマイニングされたかを
確認し、[Bitcoin アンカーの照合](#bitcoin-アンカーの照合) と同じ 3 つの
結果を返します。確認のたびに、このブロードキャストの
**承認の履歴を表示** に追加されます。この一覧は再読み込みで消えますが、
すべての結果は
[公開物の観測アーカイブ](12-ArchiveAndLeaderboards.md#公開物の観測アーカイブ)
にも残ります。

### パイプラインがしないこと

承認されたトランザクションでも、**外部の証拠** の項目は作られないので、
ほかの人がそれを証拠として発見することはできません。確認、署名、
ブロードキャストの画面は、新しい計画、新しい署名、再読み込みで消えます。
残るのは、確定時に作られる公開物の記録と、観測アーカイブにある
すべてのブロードキャストと承認の結果です。

### Bitcoin アンカーの公開

**Bitcoinアンカーの公開** カードには、このデバイスが確定したすべての
トランザクションについての記録 `{ anchor ID, content hash, txid,
network, created at }` が並びます。**トランザクションを検証して確定**
が成功したときに、そのあとのブロードキャストがうまくいくかどうかに
かかわらず作られ、承認済みや有効といった独自の状態は持ちません。
**公開を表示** で一覧表示します。各行には次のものがあります。

- **観測を調べる** — そのアンカー ID についてアーカイブにある、
  ブロードキャスト、承認、内容の証明、チェーン上の位置、整合性の各事実の
  数。
- **公開のライフサイクルを表示** — 同じ事実を時系列で、
  **公開記録を作成しました** から並べます。何も記録されていない段階は
  単に表示されません。開いてもネットワークには接続しません。

## Base のアンカーパイプライン

同じ考え方を、Ethereum 互換のネットワークである **Base** で行います。
Bitcoin とは別のもので、独自のウォレット、独自のトランザクション（内容の
ハッシュをデータとして持つ、自分宛ての送金）、独自の用語があります。

> **ウォレットがどちらのネットワークにあるかに応じて、Base メインネット
> の本物の資金、または Base Sepolia のテスト用の資金を使います。**
> ForkBuild がネットワークを選ぶことはありません。

### 必要なもの

- 標準の [EIP-1193](https://eips.ethereum.org/EIPS/eip-1193)
  `window.ethereum` インターフェースを使うブラウザーのウォレット
  （Coinbase Wallet や MetaMask など）。
- チェーン ID **8453**（Base メインネット）または **84532**（Base
  Sepolia）のアカウント。ほかのチェーンは不一致として報告されます。
- 公開物ページにある公開物。

### ウォレットを接続してアカウントを観測する

**Baseネットワーク** カード（**ウォレット・アーカイブ・公開者向けツール →
ブロックチェーンへのアンカリング** の中）で **Baseウォレットを接続** を
クリックし、承認します。状態は Bitcoin と同じく **接続中**、**未接続**、
**ウォレットを利用できません** です。**切断** で切り、再読み込みすると
忘れます。

次に **Baseアカウントを観測**（その後は **観測を更新**）が、アカウントの
チェーンと残高を読みます。

| バッジ | 意味 |
|---|---|
| **Baseアカウントを観測しました** | **ネットワーク**、**チェーンID**、**アカウント**、**ネイティブ残高**（wei 単位）、観測した時刻。 |
| **接続中のネットワークはBaseではありません** | 実際に見つかったチェーン ID を表示します。 |
| **Baseアカウントを利用できません** | ウォレットに届きませんでした。 |

### トランザクション計画を作る

公開物のカードの **分散化と証拠** タブにある **Baseの公開トランザク
ション → Baseのトランザクション計画を作成**（アカウントを観測すると
使えます）は、内容のハッシュをデータとして持つ、自分のアカウントから
自分自身への未署名の送金を作ります。

| 状態 | 意味 |
|---|---|
| **トランザクション計画を作成しました** | ネットワーク、チェーン ID、内容のハッシュ、送信元と送信先（同じアドレス）、金額、ナンス、ガスの上限、最大手数料と優先手数料（wei 単位）、データ、アカウントを観測した時刻と計画を作った時刻。 |
| **Baseネットワークを利用できません** | アカウント、手数料、ナンスを読めませんでした。 |
| **トランザクションを作成できません** | そのほかの失敗です。 |

新しい計画は、それ以前に確認、署名、ブロードキャストしたものを置き換え
ます。

### 確認して署名する

計画ができると、すぐにカードの **Baseトランザクションの確認** が埋まり
ます。送信元、送信先、金額、ナンス、ガスの数値、内容のハッシュ、
トランザクションのデータです。**確認したトランザクションに署名** は、
ウォレットにまさにその計画への署名を求めます。

| 状態 | 意味 |
|---|---|
| **ウォレットが署名済みのトランザクションを返しました** | 署名されましたが、まだ検証されていません。 |
| **署名が拒否されました** | あなたかウォレットが断りました。 |
| **ウォレットを利用できません** | ウォレットが接続されていないか、届きません。 |
| **署名に失敗しました** | ウォレットが使えないものを返しました。 |

### 1 回で Base のアンカーを作る

同じ確認のカードの **Baseアンカーを作成** は、確認したトランザクションへの
署名、確定、ブロードキャストを 1 回のクリックで行い、それを公開物の
証拠の一覧に加えます。段階ごとのボタンの代わりになるもので、段階ごとの
ボタンも引き続き使えます。

| バッジ | 意味 |
|---|---|
| **アンカーを作成しました** | ブロードキャストされ、新しいアンカーが [証拠の一覧](#証拠の一覧) に開いた状態で表示されます。 |
| **記録が拒否されました** | 署名、確定、ブロードキャストのどれかが拒否されました。 |
| **アンカーは作成されませんでした** | ウォレットかネットワークに届きませんでした。 |

その後は **Baseアンカーをもう1つ作成** になります。ウォレットを使い、
本物のトランザクションを送ります。

### 検証、確定、ブロードキャスト

**トランザクションを検証して確定** は、確認した計画に対して署名を
オフラインで確認し、署名者を復元します。

| 状態 | 意味 |
|---|---|
| **トランザクションを確定しました** | 有効です。復元した署名者とトランザクションのハッシュを表示します。 |
| **署名を検証できませんでした** | 鍵が違うか、署名が違うか、データが違います。 |
| **確定を利用できません** / **確定に失敗しました** | 確認できなかったか、そのほかの使えない結果です。 |

確定すると [Base アンカーの公開](#base-アンカーの公開) の記録が作られ
ます。次に **トランザクションをブロードキャスト** で送ります。結果は
**トランザクションをブロードキャストしました**（**トランザクションID**
付き。まだブロックには取り込まれていません）、
**トランザクションが拒否されました**、**ブロードキャストを利用できません**
のどれかです。**もう一度ブロードキャスト** は同じバイト列を送り直します。

### 取り込みを観測する

ブロードキャストしたあと、**Baseトランザクションの取り込み** セクションの
**トランザクションを観測** が、それがブロックに入っているかを確認します。

| バッジ | 意味 |
|---|---|
| **トランザクションは取り込まれました** | Base がレシートを報告しています。ブロックのハッシュ、ブロック番号、トランザクションの位置、承認数です。チェーンの再編成はまだあり得ますが、検出されません。 |
| **トランザクションは取り込まれていません** | まだレシートがありません（保留中か、送られていないかは区別されません）。 |
| **取り込みの状態を利用できません** | 確認できませんでした。 |

**トランザクションをもう一度観測** は **観測の履歴を表示** に追加します。
この一覧は再読み込みで消えますが、すべての観測は
[公開物の観測アーカイブ](12-ArchiveAndLeaderboards.md#公開物の観測アーカイブ)
にも残ります。

### Base アンカーの公開

Bitcoin と同じく、**Baseアンカーの公開** カードは、確定したトランザク
ションごとに記録 `{ content hash, txid, network, created at }` を残し
ます。**公開を表示** で一覧表示し、**公開のライフサイクルを表示** には
**公開記録を作成しました** と、それに続く各 **取り込みの観測 #N** が
表示されます。Base のブロードキャストの結果は保存されないので、
ブロードキャストの項目はありません。

外部の証拠の項目を追加するのは **Baseアンカーを作成** だけで、段階
ごとの流れが追加することはありません。

## スナップショットの配置

IPFS、Arweave、ローカルへの配置の作成は通常の機能です。**配置とIPFS**
タブの一覧と、[優先するサービスを使う](#優先するサービスを使う) より
あとのものはすべて *実験的* です。

**スナップショットの配置** は、ストレージのバックエンド（**IPFS**、
**Arweave**、またはこのデバイス自身の **ローカル** のストレージ）が、
公開物の内容のハッシュに対応するバイト列を提供できる、という署名付きの
クレームです。明日もそこにある保証ではありません。違うバックエンドの、
違う人による複数の配置が並んで存在でき、どれかが優先されることは
ありません。

### 配置を作成する

公開物のカードの **配信** セクションにある **内容** ブロックには、
バックエンドごとに **ローカルの配置を作成**、**IPFSの配置を作成**、
**Arweaveの配置を作成** のカードがあります。優先するストレージを保存
していると、ブロックの先頭にそのためのボタン（**IPFSに保存** など）が
1 つあり、これらのカードは **他のストレージの選択肢** の下に折りたたまれ
ます。どれも、このデバイスが持つ公開物のバイト列を、そのバックエンドに
渡します。

- **配置を作成しました** — 受け入れられ、新しい署名付きの配置が下に
  表示されます。
- **配置は作成されませんでした** — バックエンドに届かなかったか、
  このデバイスが内容を持っていません。

その後、ボタンは **…の配置をもう1つ作成** になります。作成できたこと
は、今バックエンドがバイト列を受け入れた、という意味でしかありません。

- **IPFS** には、既定では `http://127.0.0.1:5001` にある、自分の IPFS
  ノードの API が必要です（[コンテンツサービス](10-NetworkSettings.md#コンテンツサービス)
  で変更できます）。ノードが動いていないと、**配置は作成されません
  でした** になります。
- **Arweave** には、Wander などのウォレット拡張機能が必要です。

IPFS の配置を *読む* のにノードは不要です。**スナップショットを解決** と
**スナップショットを実体化** は公開ゲートウェイを使う
（[IPFSゲートウェイ](10-NetworkSettings.md#ipfsゲートウェイ) を参照）ので、
ほかの人が配置したコンテンツを取得できます。

### 優先するサービスを使う

**内容** ブロックの一番上の **…に保存** と、カードの
**詳細 → 配置とIPFS** タブにある **優先するサービスを使う** は、
[コンテンツサービス](10-NetworkSettings.md#コンテンツサービス) で保存した
バックエンドに配置を作ります。優先するサービスを保存しても、明示的な
ボタンや既存の配置は変わりません。何も保存していないとき、または
IPFS（リモートピン留め）を保存しているときは、**内容** ブロックには
**…に保存** の代わりにすべてのバックエンドが表示されます。

| ラベル | 意味 |
|---|---|
| **配置を作成しました** | そのバックエンドのボタンをクリックしたのと同じです。 |
| **配置は作成されませんでした** | 優先するサービスが保存されていません。 |
| **優先するサービスが見つかりません** | 保存したバックエンドがこのデバイスに登録されていないか、毎回エンドポイントの入力が必要な IPFS（リモートピン留め）です。 |

### スナップショットの配置の一覧

カードの **配置とIPFS** タブの **配置を表示** は、その公開物について
知られているすべての配置を一覧表示します。自分が作ったもの、ピアが
送ってきたもの、インポートしたブループリントのパッケージに入っていた
ものです。

| 項目 | 意味 |
|---|---|
| **ロケーター** | バックエンドが示す、バイト列の場所。 |
| **配置日時** | 主張されている配置の時刻。 |
| **公開物** / **コンテンツハッシュ** | 配置の署名が結び付けているもの。 |
| **配置者** | それに署名したアイデンティティ。 |

それぞれに最大 3 つのボタンがあります。

- **配置を調べる** — 配置自体の項目と、IPFS ではゲートウェイへの
  リンク。ネットワークには接続しません。その下の **ローカルの知識** に
  は、このデバイスがそれをどう知ったか（*ローカルで把握*、
  *パッケージのインポートで把握*、*ピアとの交換で把握*）と、
  **このレプリカでの初回確認** の時刻が表示されます。
- **スナップショットを解決**（その後は **もう一度解決**） — 保存せずに、
  今バイト列を取得できるかをバックエンドに確認します。
- **スナップショットを実体化**（その後は **もう一度実体化**） — 解決し、
  うまくいけばバイト列をこのデバイスに保存します
  （[ローカルのスナップショット](09-PublicationsAndEvidence.md#ローカルのスナップショット)
  を参照）。配置を選ぶのはあなたで、別の配置を勝手に試すことはありません。

| 実体化の結果 | 意味 |
|---|---|
| **実体化しました** | 取得し、照合し、ここに保存しました。 |
| **すでに利用可能** | このデバイスはすでに一致するバイト列を持っていました。 |
| **現在は利用できません** | バックエンドに届かなかったか、持っていません。 |
| **拒否されました** | バイト列が配置のハッシュと一致しませんでした。 |
| **無効な配置** | 記録の形式が正しくないか、本当に署名されたものではありません。 |

### 解決の結果

| バッジ | 意味 |
|---|---|
| **内容を利用可能** | バックエンドが、内容のハッシュと一致するバイト列を提供しました。 |
| **ストレージのバックエンドが設定されていません** | このデバイスには、この種類のストレージのバックエンドがありません。 |
| **内容を利用できません** | 届きましたが、今はバイト列を持っていません。 |
| **取得した内容がこの配置と一致しません** | バックエンドが違うバイト列を提供しました。 |
| **無効な配置** / **無効な署名** | 記録の形式が正しくないか、本当に署名されたものではありません。 |

結果はこの訪問の間このページに残り、共有はされません。同じ配置でも、
2 人が違う結果を得ることがあります（たとえば片方だけが IPFS ノードを
動かしている場合）。この訪問の中で以前に解決できた配置に、あとで届か
なくなった場合は、「このスナップショットは以前に解決できましたが、現在は
利用できません。」と注記されます。不一致がこのように和らげられること
はありません。

### 配置の関係

配置が 2 つ以上あると、**配置の関係** カードに、バックエンドと異なる
場所の数、内容のハッシュごとの配置の数が表示され、
**内容の結び付け: 一致** または **競合**（警告付き）と表示されます。
これはクレームだけに基づくもので、解決したかどうかは関係なく、数が多い
グループのほうが正しいと見なされることもありません。

## IPFSへの公開

*実験的。* カードの **配置とIPFS** タブで、スナップショットの配置の下に
ある **IPFSへの公開** セクションは、あなたが選んだピン留めサービスに
内容をアップロードします。（セクションにあるとおり、ローカルの Kubo
ノードは解決も公開もでき、リモートのゲートウェイは解決だけ、リモート
ピン留めは公開だけができます。）配置と違い、結果はほかの人が発見できる
署名付きのクレームではなく、サービスがそのバイト列を受け入れたという
記録です。画面上の結果は再読み込みで消えますが、成功したすべての公開と
すべての検証は
[公開物の観測アーカイブ](12-ArchiveAndLeaderboards.md#公開物の観測アーカイブ)
にも残ります。

### リモートのピン留めサービスを設定する

ForkBuild には組み込みのピン留めサービスはありません。
**リモート公開を設定**（その後は **リモート公開を再設定**）をクリック
します。

| 項目 | 意味 |
|---|---|
| **エンドポイント** | サービスのアップロード用 URL。必須です。 |
| **認証情報**（任意） | bearer の `Authorization` ヘッダーとして送られます。表示されることはなく、カードには **設定済み** か **未設定** とだけ表示されます。 |
| **リクエストのフィールド**（任意） | ファイル用のフォームのフィールド。既定は `file`。 |
| **レスポンスのフィールド**（任意） | CID を含むレスポンスのフィールド。既定は `cid`。 |

**設定を保存** は、この訪問の間だけ設定を保持します。保存されることは
なく、再読み込みか **設定をクリア** で破棄されます。キャンセルすると
前の設定が残ります。再設定するとやり直しになり、新しいサービスでは
まだ何も公開されていない状態になります。

### 公開する

**リモートIPFSに公開**（その後は **もう一度公開**）は、このデバイスの
コピーを内容のハッシュと照合してからアップロードします。

| バッジ | 意味 |
|---|---|
| **公開済み** | 受け入れられ、サービスが CID を返しました。 |
| **公開が拒否されました** | 拒否されました。たとえば認証情報の誤り、リクエストの形式の誤り、容量の上限です。再試行する前に設定を変えてください。 |
| **公開を利用できません** | サービスに届きませんでした。あとでもう一度試してください。 |
| **公開に失敗しました** | そのほかすべて。先に行うローカルの整合性確認の失敗も含みます。 |

公開した結果には、内容のハッシュ、ロケーター（`ipfs://<cid>`）、
エンドポイント、時刻が表示されます。
[告知 / 発見サービス](10-NetworkSettings.md#告知--発見サービス) の名前が
付いた **Nostr: 告知済み** や **Steem: 未告知** のようなバッジは、
公開がスナップショットの発見のためにも告知されたかどうかを示し、
ローカルのノードからの公開と同じように、ほかの人が見つけられるかを
表します。**未告知** は告知だけが失敗したという意味です。

### 公開したものを検証する

公開が成功したあと、**内容の取得 → IPFSの内容を検証**（その後は
**もう一度検証**）が、あなたの
[IPFSゲートウェイ](10-NetworkSettings.md#ipfsゲートウェイ) を通して
バイト列を取得し、記録されたハッシュと比べます。

| バッジ | 意味 |
|---|---|
| **取得した内容は記録されたコンテンツハッシュと一致しています** | 一致します。 |
| **取得した内容が記録されたコンテンツハッシュと一致しません** | 一致しません。 |
| **内容の取得を利用できません** | ゲートウェイに届かなかったか、持っていません。不一致ではありません。 |
| **検証に失敗しました** | ほかの何かがうまくいきませんでした。 |

### 公開の履歴

もう一度公開しても、以前の記録が上書きされることはありません。
**公開の履歴を表示** は、すべての公開を古い順に、ロケーターと時刻付きで
一覧表示します。**調べる** は、そのロケーター、内容のハッシュ、時刻、
方法（現在は常に **リモートピン留めサービス**）を表示します。各項目
には独自の **内容を検証** ボタンと、その記録のすべての確認を時系列で
並べた **検証の履歴を表示** があります。

## Steem

*実験的。* ForkBuild は Steem ブロックチェーンで告知、保存、共有が
できます。告知（公開物、スナップショット、コメントの告知）は、
[`@forkbuild/forkbuild-snapshot-2026-09`](https://steemit.com/forkbuild/@forkbuild/forkbuild-snapshot-2026-09)
のような毎月の発見用スレッドへの返信です。読むのにアカウントは不要です。
見つかったものは、Nostr や Arweave の告知と同じように検証され、投票、
報酬、評判は影響しません。設定は
[ネットワーク設定 → Steem](10-NetworkSettings.md#steem) にあります。

### Steem に投稿する

配信ダイアログ、公開物ページ、または **コメントを投稿** の横で
**Steem** を選ぶか、
[告知 / 発見サービス](10-NetworkSettings.md#告知--発見サービス) で既定に
します。アカウントの **投稿** 鍵を持つ Steem Keychain 拡張機能と、Steem
の設定ページに保存したアカウント名が必要です。ForkBuild が鍵を見ること
はありません。各投稿は、報酬を辞退した、今月のスレッドへの返信で、
Keychain が承認を求めます。今月のスレッドがまだない場合は、何も投稿
されず、その旨が表示されます。コメントは必ずまずこのデバイスに保存され、
アカウントや Keychain がない場合はフォームで警告されます。

### Steem に保存する

配信ダイアログか公開物ページで、ストレージとして **Steem** を選びます。
スナップショットは圧縮され、今月のコンテンツ用スレッド（
`@forkbuild/forkbuild-content-2026-10` など）への返信として、ピン留めも
アップロードの手数料もなしに保存されます。データは各投稿のメタデータに
入り、投稿の本文は 1 行のメモです。データが本文にある古い投稿も読み込め
ます。

- **サイズ。** 約 2,500 個のブロックまでなら 1 つの投稿に収まります。
  それより大きい作品は、1 つの目次の投稿と、約 48 KB の投稿が最大 20 個
  で、約 30,000 個のブロックまでです。それより大きいものは投稿前に拒否
  され、IPFS か Arweave を使うよう案内されます。
- **承認。** Keychain は投稿ごとに、少なくとも 4.5 秒の間隔で承認を
  求め、ダイアログには進み具合（「Steemに保存中: 9件中3件を投稿しま
  した。」）が表示されます。
- **リソースクレジット。** 投稿にはアカウントのリソースクレジットを使い、
  5 日かけて回復します。足りなければ何も投稿されず、どれだけ必要かが
  表示されます。進み具合には使う割合も表示されます。
- **途中で止まった場合**（断った、クレジットが尽きた、接続が切れた）は、
  いくつの投稿が保存されたかが表示されます。同じアカウントでもう一度
  配信すると、足りない投稿だけが作られます。すべての投稿が保存される
  まで、何も告知されません。

署名済みクレームも Steem に保存できます。同じスレッドへのもう 1 つの
投稿（と承認）で、両方を配信するときはスナップショットのあとになります。
Arweave のものと同じように読み戻され、署名が確認されます。

### リンクを共有する

**Steem 上で。** 署名済みクレームの投稿には、作品の画像、タイトル、
あなたの名前と説明、そして「See it in 3D」（3D で見る）というリンクが
表示されます。Keychain が画像への署名の承認を求め、画像はリソース
クレジットを使わずに Steemit の画像ホストにアップロードされます。断ったり
作れなかったりした場合は、画像なしで投稿されます。タイトルや説明の
中のメンション、タグ、リンクは普通のテキストとして表示されるので、
誰にも通知されません。リンクをクリックした人は、ForkBuild を使ったことが
なくても、ForkBuild が共有ワールドの署名と、作品が告知と一致することを
確認したあと（一致しなければページに理由が表示されます）、ワールド
ビューであなたの作品のところに着きます。作品はその人のブラウザーに保存
されます。リンクには、作品が保存されているだけでなく告知されている
ことも必要で、配信がその両方を行います。

**どこでも。** 署名済みクレームを Steem、Arweave、IPFS に保存すると、
その下に **共有…** と **リンクをコピー** が表示されます。ワールド
ビューの公開物のパネル、配信ダイアログの結果、公開物ページです。
**共有…** は、使える場合はデバイスの共有シートを開きます。
**リンクをコピー** はリンクをコピーし、手でコピーできるようにリンクも
表示します。スナップショットも配信していれば、リンクはどのデバイスでも
開け、建物はあなたが配置した場所に表示されます。署名済みの配置はスナップショットと一緒に届き、リンクがそれを取り込みます。アドレスバーにある `#/world/…` のアドレスは、自分のブラウザー
でしか使えません。

- **Arweave:** 配信した直後は、アップロードがゲートウェイに届くまで、
  リンクが開けるようになるのに数分かかることがあります。ページには
  **再試行** が表示されます。
- **自分のノードの IPFS:** ノードがオンラインで、公開ゲートウェイから
  届く間だけ開けます。ピン留めサービスか Arweave を使えば、コンピューター
  の電源が切れていても利用できます。
- 友達は、自分のネットワーク設定にあるゲートウェイを通して読みます。
  IPFS のゲートウェイには、クレームを見つけるのに最大 30 秒かかります。

## Blurt

*試験的。* Blurt は Steem から派生した、ダウンボートのないブロック
チェーンです。ForkBuild はそこで告知、保存、アンカーができ、すべては
**あなた自身のアカウント** から、報酬を受け取れる通常の Blurt 投稿として
出ていきます。作品の投稿がアップボートされると、BLURT を獲得できます。
ForkBuild のアカウントも共有スレッドもありません。設定は
[ネットワーク設定 → Blurt](10-NetworkSettings.md#blurt) にあります。

### Blurt に投稿する

配信ダイアログ、公開物ページ、**コメントを投稿** の横、または命名パネルで
**Blurt** を選ぶか、
[告知 / 発見サービス](10-NetworkSettings.md#告知--発見サービス)
で既定にします。アカウントの **投稿** キーを入れた Blurt Keychain 拡張
機能（または WhaleVault）と、Blurt の設定ページに保存したアカウント名が
必要です。ForkBuild がキーを見ることはなく、Keychain が投稿のたびに
承認を求めます。

- **作品ごとに 1 つの投稿。** 配信すると、あなたのアカウントから
  トップレベル投稿が 1 つ作られます。タグは `forkbuild` と、
  `forkbuild-snapshot` または `forkbuild-publication` で、作品の画像、
  タイトル、あなたの名前と説明（2,000 文字まで全文）、そして「See it in 3D」（3D で見る）という
  リンクが入ります。その後 30 分以内に続くもの（公開物の告知、コメント、
  アンカー）は、同じ投稿を編集して追加されるので、フォロワーには複数では
  なく 1 つの投稿として見えます。
- **画像には別の承認が必要です。** 署名済みクレームの場合、Keychain は
  まず作品の画像への署名を、次に投稿の承認を求めます。2 つ目のウィンドウは
  ブラウザーの後ろに開くことがあります。ForkBuild はそれぞれ最大 2 分
  待ちます。画像は Blurt の画像ホストに送られます。ブラウザーから直接
  届かないときは ForkBuild のランデブーサーバーを経由します。
  アップロードできなかった場合、投稿は画像なしで出ていきます。
- **投稿の間隔は 5 分。** Blurt は、1 つのアカウントにつき 5 分ごとに
  1 つのトップレベル投稿しか受け付けません。あなたのアカウントが最近
  投稿していた場合（たとえば別のアプリから）、ForkBuild は待ち、
  ダイアログにどれくらい待つかが表示されます。
- **手数料。** Blurt のトランザクションには、Blurt のウィットネスが決める
  少額の BLURT 手数料がかかります。アカウントが払えない場合は何も投稿
  されず、そのことが知らされます。
- **ほかの人が見つける** には、Blurt の検索インデックスである Nexus を
  使います。Nexus は ForkBuild のタグの付いた投稿を、どれほど古くても
  すべて一覧にします。Nexus を提供する Blurt ノードがない場合、ForkBuild は
  投稿を 1 週間だけ一覧にするタグを読み、次にあなたのアカウントの履歴を
  読みます。誰かの ForkBuild があなたの投稿を一度見つけると、それより
  新しい投稿も古い投稿も読み続けます。

### Blurt に保存する

配信ダイアログまたは公開物ページで、ストレージとして **Blurt** を
選びます。作品は Steem と同じように、作品の投稿の下の返信に保存されます。
1 つの返信に約 2,500 ブロックまで、または最大 20 件の追加の返信で約
30,000 ブロックまでです。投稿する前に ForkBuild は手数料を計算し、残高が
足りなければ断ります（「この作品を Blurt に保存するには約 0.632 BLURT の
手数料がかかりますが、アカウントの残高は 0.100 BLURT です」）。
ダイアログには進み具合と手数料が表示されます。途中で止まった場合は、
同じアカウントでもう一度配信すれば、足りない返信だけが作られます。

署名済みクレームも、もう 1 つの返信として Blurt に保存できます。その
リンクは Steem のものと同じように動きます。「See it in 3D」をクリック
した人は、ForkBuild が確認したあと、ワールドビューであなたの作品の
ところに着きます。保存されると **共有…** と **リンクをコピー** が
表示されます。
