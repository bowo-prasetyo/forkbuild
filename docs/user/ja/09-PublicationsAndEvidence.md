**公開物** ページは、リポジトリより技術的な層です。リポジトリが扱うのは
ドキュメントとワールドです。公開物ページが扱うのは「この構造物を
デザインしたのは私です」「この場所を X と呼びます」といった
**署名されたクレーム** と、クレームに付け加えられる任意の奥行きです。

- **このガイド** — クレームの出どころ、公開物ページ、
  [コメント](#コメント)、そして
  [ローカルのスナップショット](#ローカルのスナップショット)（デバイスが
  保持しているもの）。
- **[ネットワーク設定](10-NetworkSettings.md)** — ゲートウェイ、リレー、
  サービス、ピア接続用のサーバー。試験的ではなく、誰にとっても役に立ち
  ます。
- **[証拠とストレージ](11-EvidenceAndStorage.md)** — 外部証拠
  （Bitcoin、Base、Arweave、Steem）、ウォレットのパイプライン、
  スナップショットの配置、IPFS への公開、Steem。
- **[アーカイブとリーダーボード](12-ArchiveAndLeaderboards.md)** — 永続的な
  観測アーカイブ、参照、実績、公開者ラベル、リーダーボードのページ。

## 「公開」の 2 つの意味

| | **公開**（リポジトリ） | **公開物ページ** |
|---|---|---|
| 共有するもの | ドキュメントまたはワールド | 署名された記録: 共有ワールド、構造物の作者情報、地名 |
| 見る場所 | リポジトリ、作者のページ、ワールドビュー | **公開物** ページ |
| できること | 開く、探索、フォーク | 確認する、内容を取得する、配信してアンカーする |
| ガイド | [公開とフォーク](04-PublishingAndForking.md) | このガイド |

**公開** しただけでは、ワールドは公開物ページに載りません。
**ピアと共有** で載ります。ワールドに、ピアのところへ移動できる
**共有ワールド** として署名するからです（[分散化されたリポジトリの作品](#分散化されたリポジトリの作品)
を参照）。

公開物ページには、共有ワールドであっても **開く**、**探索**、
**フォーク** はありません。表示するのは署名された記録で、ワールドでは
ありません。共有ワールドを開く、探索する、フォークするには、リポジトリ、
作者のページ、ワールドビューで見つけてください。ピアから受け取った
ものは、その内容がこのデバイスに届くとそこに表示されます。（唯一の
例外は、もう一度公開する必要がある自分の共有ワールドの
**エディターで開く** です。[状態の意味](#状態の意味) を参照してください。）

公開物ページの項目はどれも *公開物* で、次の 3 種類のどれかです。

| 種類 | 内容 |
|---|---|
| **共有ワールド** | ピアやネットワークの間を移動できる署名された記録としての、公開されたワールド |
| **ブループリントの作者情報** | 構造物をデザインしたというクレーム |
| **地名の主張** | 地域やランドマークの名前 |

ワールドビュー、エディター、リポジトリでも、ワールドの署名された記録を
**共有ワールド** と呼びます。**自分の共有ワールド**、
**共有ワールドを発見**、**共有ワールドに戻る** などです。

## 公開物を取り巻くもの

公開物とは、署名された記録だけのことです。カードやワールドビューで
その周りに見えるほかのものは、すべてそれを使って行ったこと、または
それに付けられたものです。どれも公開物の一種ではなく、必須なのは
公開物そのものだけです。

| 用語 | たとえると… | 内容 |
|---|---|---|
| **公開物** | 本そのもの | 署名された記録: 共有ワールド、ブループリントの作者情報、地名の主張。内容のハッシュと公開者の署名を持っています。 |
| **内容** | 印刷した本の保管場所 | 公開物が扱うバイト列（ワールドのブロックなど）。必ずまずこのデバイスに保存され、**…に保存** が IPFS、Arweave、Steem にコピーを置いて、ほかの人が取得できるようにします。[コンテンツサービス](10-NetworkSettings.md#コンテンツサービス) を参照。 |
| **スナップショット** | 印刷した 1 冊 | 公開物の内容（ワールドのブロックなど）を保存した 1 つのコピー。ほかの人が取得し、ハッシュと照合できます。[ローカルのスナップショット](#ローカルのスナップショット) を参照。 |
| **配置** | その本を置く棚 | 作品がワールドのどこにあるかの署名された記録。1 つの共有ワールドに複数の配置があり得ます。[配置とフォークの違い](03-WorldView.md#配置とフォークの違い)を参照。 |
| **告知 / 発見** | 図書館の目録の項目 | Nostr、Arweave、Steem 上の小さな署名されたお知らせで、公開物やスナップショットがあることと、コピーがどこにあるかを示し、あなたと接続していない人が見つけられるようにします。[告知 / 発見サービス](10-NetworkSettings.md#告知--発見サービス) を参照。 |
| **証明 / アンカリング** *（実験的）* | 公証人の印 | 内容のハッシュをブロックチェーンのトランザクション（Bitcoin、Base、Arweave、Steem）に書き込み、その時点で存在していた証拠にします。何も保存も告知もしません。[証拠とストレージ](11-EvidenceAndStorage.md) を参照。 |
| **コメント** | 読者のレビュー | サインインした人なら誰でも公開物に付けられるコメント。それぞれ、公開者ではなくコメントした人が署名します。[コメント](#コメント) を参照。 |

つまり、公開物を作り、必要ならその内容を保存し、告知し、アンカーし、
（共有ワールドなら）配置します。そして誰でもそれにコメントできます。

## 公開物の出どころ

公開物ページそのものでクレームを作ることはありません。ページに並ぶ
のは、ほかの場所であなたが作ったクレーム、ピアが送ってきたクレーム、
分散型の形で届いたリポジトリの作品です。地名のクレームは、ピアを
介さずに Nostr から直接見つけることもできます。
[近くの地名](03-WorldView.md#近くの地名--誰のクレームでも見つける)
を参照してください。

### 構造物の作者であることを主張する

エディターのビルドライブラリの **マイ構造物** から、構造物の **情報**
パネルを開きます。ブループリントの ID を持っていれば（保存した構造物の
ほとんどが持っています）、**コミュニティによる作者情報** のセクションに
次のものがあります。

- **作者であることを主張** — 今のアイデンティティで、自分がデザイン
  したというクレームに署名します。主張するまで表示されます。
- **作者情報をエクスポート** — クレームを、誰かに渡せるファイルとして
  保存します。
- **ネットワークに公開** — 接続しているすべてのピアにクレームを告知し、
  相手とあなた自身の公開物ページに載せます。

### 場所に名前を付ける

ワールドビューで地域かランドマークの名前を付けるパネルを開き、
**名前を公開** を使います（[地理的な場所](03-WorldView.md#地理的な場所)
を参照）。署名されたクレームが、接続しているピアに告知されます。

[近くの地名](03-WorldView.md#近くの地名--誰のクレームでも見つける)
でも名前を見つけてもらえるようにするには、名前を付けるパネルの
**その他** を開き、**すべての主張** でクレームを見つけて **Nostrに公開**
をクリックします。これは別の手順で、どちらの操作ももう一方を行いません。
成功すると届いたリレーの名前が表示され、失敗すると（多くは Nostr の
ブラウザー拡張機能が入っていないため）エラーが表示されます。

### ピアから受け取る

ピアと接続すると（[ピア接続と友達](07-PeerConnectionsAndFriends.md) を
参照）、あなたのデバイスは、接続している間に公開されたものだけでなく、
相手が公開したものすべてを受け取ります。受け取ったクレームは、正しく
署名された記録にすぎません。内容は、**ピアから取得**（下記）で取得する
まで、あなたのデバイスにはありません。

### 分散化されたリポジトリの作品

カードには **共有ワールド** が入ることもあります。リポジトリの一覧と
同じ種類のものを、分散型で移動できるように包んだものです。リポジトリの
**ピアと共有** は、自分のワールドについてこれを作ります
（[接続中のピアと共有する](04-PublishingAndForking.md#接続中のピアと共有する)
を参照）。ここで **再確認** か **ピアから取得** でそれを解決すると、
リポジトリの検索、作者のページ、ワールドビューに加わり、再読み込み
しても残ります。

## 公開物ページ

上部のバーで **公開物** を開きます。このデバイスが目録に入れたすべての
署名された公開物が、自分のものもピアのものも表示されます。一番下に
折りたたまれた **ウォレット・アーカイブ・公開者向けツール** のパネル
には、ページ全体のための道具が 3 つのタブで入っています。
**ブロックチェーンへのアンカリング**、**アーカイブツール**、
**参照と実績** です（ガイド [11](11-EvidenceAndStorage.md) と
[12](12-ArchiveAndLeaderboards.md) を参照）。ページの冒頭にあるリンクや、
先にウォレットの観測が必要な手順のリンクから開くと、パネルが自動で
開きます。

各公開物のカードには、次のものが表示されます。

- 内容を確認したあとは、その名前（共有ワールドのタイトルや地名）。
  それ以外のときや作者情報のクレームでは、公開物の種類。
- 公開物の種類（名前があるときはその下）と、公開した人（ID の末尾
  数文字に短縮）。
- **状態のバッジ**（[状態の意味](#状態の意味) を参照）。ページを読み込む
  たび、また **再確認** をクリックするたびに判定し直されます。
- クレームの 1 行の概要: 作者情報なら指紋と主張した人、地名なら名前と
  主張した人。
- 内容が利用できない間は **ピアから取得**（ピアが接続していないと
  使えません）。接続中の各ピアに順番にバイト列を求め、デバイスが内容の
  ハッシュと照合したあとにだけ受け入れます。
- **再確認** — 今すぐ状態を判定し直します。

その下に、折りたたまれた 2 つのセクションがあります。

- **配信** — 公開物を告知し、内容を保存し、アンカーします。保存と
  アンカーには、それぞれ **設定** で保存したサービス用のボタンが先頭に
  1 つあり（**IPFSに保存**、**Steemにアンカー**）、ほかのサービスは
  すべて **他の…の選択肢** の下に折りたたまれています。使える
  サービスを保存していないと、すべての選択肢が表示されます。Steem と
  リモート IPFS ピン留めは、表示されるところではどこでも **実験的** と
  示され、**証明 / アンカリング** のブロック全体も同様です。
  [公開物ページから配信する](#公開物ページから配信する) と
  [証拠とストレージ](11-EvidenceAndStorage.md) を参照してください。
- **詳細** — 4 つのタブがあります。

| タブ | 内容 |
|---|---|
| **スナップショット** | [ローカルのスナップショット](#ローカルのスナップショット): このデバイスが保持しているものと、その取得方法。 |
| **分散化と証拠** *（実験）* | [分散化](#分散化の概要)、[証拠の一覧](11-EvidenceAndStorage.md#証拠の一覧)、Bitcoin と Base のトランザクションの手順。 |
| **配置とIPFS** *（実験）* | [スナップショットの配置](11-EvidenceAndStorage.md#スナップショットの配置) の一覧と [IPFSへの公開](11-EvidenceAndStorage.md#ipfsへの公開)。 |
| **履歴** *（実験）* | **ドメイン横断のタイムラインを表示**: この公開物についての IPFS と Bitcoin のすべての観測を時系列で。 |

### 状態の意味

| バッジ | 意味 |
|---|---|
| **利用可能** | 内容が今このデバイスにあります。 |
| **内容を利用できません** | クレームは本物ですが、内容がまだここにありません。**ピアから取得** を試してください。 |
| **公開物のエンベロープが無効です** / **公開物の署名が無効です** | 記録の形式が正しくないか、本当に署名されたものではありません。 |
| **内容が自身の参照と一致しません** / **内容が無効です** / **内容の署名が無効です** | 内容が、公開物が主張しているものと一致しません。 |
| **ドメイン固有の確認に失敗しました** | 形式は正しく署名もされていますが、その種類に固有の確認に失敗しています。 |
| **対応していない種類の公開物です** | このバージョンでは、この種類の公開物を表示できません。 |

これらは記録が正しいかどうかを示すもので、デザインや名前の良し悪しを
示すものではありません。

状態が **利用可能** でも **内容を利用できません** でもない公開物は、
開く、配信する、アンカーすることができないので、完全なカードは表示され
ません。これらはページの一番下に、「使用できない公開物が *N* 件あり
ます」という折りたたまれたグループとしてまとめられ、それぞれに状態、
理由、**再確認**、**このデバイスから削除** があります。
**複数の公開物を…にアンカー** からも除かれます。いちばん多い理由は、
内容のハッシュが SHA-256 になる前に作られた公開物であることです。
これを直せるのは作者だけで、もう一度公開する必要があります。

このうち **あなたの** もの（このデバイスのアイデンティティが署名した
もの）で、古いハッシュのためだけに失敗しているものは、**自分のもの** の
バッジ付きで先頭に表示されます。「作者がもう一度公開する必要があります」
の代わりに、その方法が表示されます。

| 種類 | もう一度公開する方法 |
|---|---|
| **共有ワールド** | エディターでワールドをもう一度公開し、リポジトリでその下の **ピアと共有** をクリックします（**リポジトリを開く**）。 |
| **ブループリントの作者情報** | エディターで構造物の **情報** パネルを開き、**このデザインに再署名** してから **ネットワークに公開** します（**エディターを開く**）。 |
| **地名の主張** | ワールドビューでその場所の名前を付けるパネルを開き、もう一度 **名前を公開** します。 |

ワールドの場合、あなたが公開したものについての自分の記録がまだこの
デバイスにあれば、カードはさらに一歩進みます。カードにはワールドの
名前（**共有ワールド** ではなく **My Castle** など）が付き、
**エディターで開く** でそのワールドが開いて、すぐにもう一度公開でき
ます。名前とリンクはあなた自身の記録から来るもので、誰も確認できない
古い項目の内容から来ることはありません。記録がない場合（その後その
ワールドの公開を取り消した場合）、カードには上と同じく
**リポジトリを開く** が表示されます。

新しいコピーには独自のカードができるので、そのあと古いものを削除して
ください。古いものは、あなたのものであっても決して受け入れられません。
このデバイスはピアから受け取った内容も保存しているので、古いハッシュでは
あなたがどのバイト列を公開したかを証明できないからです。

**このデバイスから削除**（またはグループ上部の
**N件すべてをこのデバイスから削除**）は、確認を求めてから、ここでその
公開物を忘れます。何かの公開を取り消すことも、ほかの誰かに届くことも
なく、その公開物をまだ持っている接続中のピアが、もう一度告知すること
もあります。削除できるのは、このグループの公開物だけです。

### 公開物ページから配信する

**配信 → 告知 / 発見** には 2 つのカードがあります。

- **公開物** は、署名された公開物そのものを、選んだ **基盤**（Arweave、
  Nostr、または実験的な Steem）で告知します。最初は
  [告知 / 発見サービス](10-NetworkSettings.md#告知--発見サービス) に
  なっています。
- **スナップショット** は、内容を **内容** の下で保存し、独自の
  **基盤** で告知します。これも最初はそのサービスになっています。
  ワールドの場合は、ワールド自体のスナップショットで、このデバイスが
  公開者の署名付きの配置を持っていれば、ワールドビューの **配信** と
  同じように、公開者がそれを置いた場所と一緒に告知します。ほかの種類の
  場合は公開物の内容で、そのハッシュだけで告知します。このデバイスには
  バイト列が必要です。開いたことのないワールドなら、先にワールドビューで
  開くか、ピアから取得してください。

結果には使った基盤（**Steem: 告知済み** など）が表示され、ワールドの
場合は公開者の配置が一緒に送られたかどうかも示されます。**未告知** は
告知だけが失敗したという意味で、内容は保存されています。

## コメント

サインインしたアイデンティティなら誰でも、解決できるどの公開物にも
コメントできます。リポジトリの作品、作者情報のクレーム、地名です。
所有者の確認、友達関係の条件、モデレーションはありません。

コメントは次の場所にあります。

- **リポジトリ** と作者のページ: すべてのカードとリストの行にある
  **コメント** ボタン。
- ワールドビューの
  [自分の共有ワールド](03-WorldView.md#自分の共有ワールド--ピアなしで自分のスナップショットを配信する)
  パネルの **コメント** セクション。
- 選択した **ワールドでの出会い** の **コメント** ボタン。

どれも、コメントを古い順に、それぞれの作者のアイデンティティ付きで
表示します。サインインしていればテキスト欄と **コメントを投稿** が、
そうでなければサインインを促すメモが表示されます。

コメントは永続的です。編集、削除、返信はできません。

### コメントの届き方

**リポジトリ** から投稿したコメントは、あなたのデバイスに保存され、
接続しているピアに送られ、**コメントを投稿** の横で選んだネットワーク
（Nostr、Arweave、Steem。最初は
[告知 / 発見サービス](10-NetworkSettings.md#告知--発見サービス) に
なっています）に公開されるので、接続していなかった人も見つけられます。
セクションを閉じると（**コメントを隠す**）、入力したまま投稿していない
ものは破棄されます。ワールドビューの **自分の共有ワールド** や
**ワールドでの出会い** から投稿したコメントは、今のところあなたの
デバイスに保存されるだけです。

ほかの人のコメントは、次のようにして届きます。

- 接続中のピアからは、投稿されたときに。
- ネットワークからは、公開物のコメントを開いたときと、
  **新しいコメントを確認** をクリックしたときに。オフラインの間に
  投稿されたコメントは、こうして見られます。

ボタンの横の行には、最後の確認の結果（*新しいコメントが2件見つかり
ました*、または応答したネットワークだけについての *新しいコメントは
ありません* など）が表示されます。到達できないネットワークは名前が
示され（*Arweaveは利用できません*）、どれも応答しなければ
*Nostr、Arweaveに接続できませんでした — このデバイスに保存された
コメントを表示しています。* と表示されます。確認されるのは、コメントを
開いた公開物だけです。取得したコメントはすべて署名が確認され、二重に
数えられることはありません。

あなたが公開した公開物に誰かがコメントすると、
[通知の履歴](03-WorldView.md#方向と場所)
（ヘッダーの 🔔 ボタン）に **Publication commented**（公開物にコメントが
付きました）の項目が表示されます。現在 ForkBuild にある通知はこの
種類だけです。

## ローカルのスナップショット

カードの **スナップショット** タブにある **ローカルのスナップショット**
は、1 つの問いに答えます。このデバイスは今、この公開物の内容のバイト列を
持っているか、です。署名や配置は確認せず、ネットワークに接続するのは、
取得の操作のどれかをクリックしたときだけです。

### 持っているものを確認する

**ローカルのスナップショットを確認**（その後は **もう一度確認**）:

| バッジ | 意味 |
|---|---|
| **利用可能** | バイト列がここにあり、内容のハッシュと一致します。 |
| **利用不可** | このハッシュで何かが保存されたことは一度もありません。 |
| **ハッシュ不一致** | このハッシュで何かが保存されていますが、もう一致しません。 |

同じ公開物を持つ 2 人でも、ストレージが違うので答えが違うことがあり
ます。確認のあとには、*公開物: ローカルで既知 / ローカルで未知 ·
スナップショット: 利用可能 / 利用不可* という行が表示されます。この
デバイスが署名された公開物を目録に入れているかどうかと、正しいバイト列を
持っているかどうかです。

### バイト列を取り込む

3 つの操作があり、それぞれ別にクリックします。

**スナップショットをインポート** — **公開物スナップショット転送
パッケージ**（1 つの公開物の内容を収めた JSON のまとまり）のための
ファイル選択と貼り付け欄を表示します。選ぶか貼り付けて、もう一度
**スナップショットをインポート** をクリックします。

| バッジ | 意味 |
|---|---|
| **インポートしました** | 保存され、ハッシュと照合されました。 |
| **すでに利用可能** | 一致するバイト列がすでにここにありました。 |
| **インポートが拒否されました** | パッケージのバイト列が、パッケージ自身のハッシュと一致しません。 |
| **スナップショットはインポートされませんでした** | 正しいパッケージではありません。 |

**ピアからスナップショットを取得** — 接続中のピアを 1 人選んで
**ピアからスナップショットを取得** をクリックします（その後は
「…もう一度」）。尋ねるのはそのピアだけです。

| バッジ | 意味 |
|---|---|
| **取得しました** | ピアのバイト列が内容のハッシュと一致します。 |
| **すでに利用可能** | 一致するバイト列がすでにここにありました。 |
| **現在は利用できません** | ピアが応答しなかったか、持っていません。 |
| **拒否されました** | ピアのバイト列が一致しませんでした。 |

配置からの **スナップショットを実体化**（
[スナップショットの配置](11-EvidenceAndStorage.md#スナップショットの配置)
を参照）が 3 つ目の方法です。3 つのどれかが成功すると、**出所:** の行に
最後に成功したもの（「転送パッケージ」「配置」「ピア」）が表示されます。

### ピアが何を持っているか尋ねる

下の **概要** と同じく *実験的* です。

**ピアのスナップショット保有状況** は、取得せずに、1 人のピアに
バイト列を持っているかを尋ねます。ピアを選んで **ピアに確認** を
クリックします（その後は「…もう一度」）。答えは **観測:** の時刻付きで、
**ピアはスナップショットを持っていると報告しています**、
**ピアはスナップショットを持っていないと報告しています**、
**ピアから応答がありません** のどれかです。新しい確認は前の結果を
置き換えます。

**ピアのスナップショット保有状況の比較** は、複数のピアに尋ねます。
ピアにチェックを入れて **選択したピアを確認** をクリックします（その後は
「…もう一度」）。表に、各ピアの報告（**保有**、**非保有**、**判定不能**）
とその時刻、合計が表示されます。**観測の履歴を表示** は、この訪問での
すべての確認を 1 行ずつ（`20:21:04 — Alice → 保有` のように）一覧
表示します。行をクリックすると、完全な報告、公開物、内容のハッシュが
表示されます。1 行は、そのときピアが言ったことの記録で、書き換えられる
ことはありません。

### 概要

- **スナップショットの取得** — 何かを確認したり試したりすると、
  セクションの一番上に表示されます。**現在の保有状況**（上の確認）と
  **取得の履歴**（この訪問での試行の、結果と出所ごとの数）です。この
  2 つは独立しています。保存に成功した試行があっても、バイト列が今も
  ここにあるとは限りません。ない場合は、取り込む 3 つの方法が案内され
  ます。何かが自動で再試行されることはありません。
  **取得の履歴を表示** は、各試行（`20:16 — ピア → ハッシュ不一致` の
  ように）を一覧表示し、クリックすると結果、公開物、内容のハッシュが
  表示されます。
- **スナップショットの状態** — その下に、この訪問で集めた事実を並べて
  表示します。**内容**、**ローカルでの保有**、**取得**、**配置**、
  **ピアの観測** です。どれも観測したあとにだけ表示され、1 つの判定に
  まとめられることはありません。

## 分散化の概要

*実験的。* **分散化と証拠** タブでは、公開物にアンカーか配置が
あると、**分散化** が
[外部証拠](11-EvidenceAndStorage.md#外部の証拠) と
[スナップショットの配置](11-EvidenceAndStorage.md#スナップショットの配置)
を比べます。

- **公開物: ローカルで既知 / ローカルで未知** — このデバイスが署名された
  公開物を目録に入れているかどうか。
- 2 枚のカードに、それぞれの種類のクレームがいくつ知られているかと、
  それらが内容のハッシュについて一致しているか（**一致**）、いないか
  （**競合**）が表示されます。片方が一致し、もう片方が競合している場合は、
  そう説明する文が表示されます。一方の一致が、もう一方を保証するわけでは
  ありません。ある種類のクレームがまだない場合は、代わりに
  **まだ比較するものがありません** と表示されます。
- **ピアと同期**（その後は **もう一度同期**）は、接続中の各ピアに、
  あなたが持っていないアンカーと配置を求め、種類ごとに **新しい主張**
  と **既知** を報告します。
- **レプリカの知識を表示** は、各アンカーと配置について、このデバイスが
  それをどうやって知ったか（**取得**: *ローカルで把握*、
  *パッケージのインポートで把握*、*ピアとの交換で把握*）、
  **初回確認**、現在の **検証** / **解決** の状態を一覧表示します。
  ネットワークには接続しません。

## 再読み込みしても残るもの

署名されたクレームと記録された事実は残ります。確認、試行、途中の画面は
残りません。

| このデバイスに残るもの | 再読み込みでリセットされるもの |
|---|---|
| 目録に入れた証拠と配置、それぞれの **ローカルの知識** | **証拠を検証** と **スナップショットを解決** の結果 |
| インポート、取得、実体化したスナップショットのバイト列 | **ローカルのスナップショット** のほかのすべて: 確認、試行の履歴、**出所:** の行、ピアへの確認と比較 |
| **分散化** の数（読み込むたびに計算されます） | **ピアと同期** の結果 |
| — | **IPFSへの公開**: サービスの設定、結果、画面上の履歴、検証の履歴 |
| 確定時に作られる **Bitcoin/Baseアンカーの公開** の記録 | ウォレットのパイプラインの接続、資金やアカウントの観測、計画、確認、署名、確定したトランザクション、ブロードキャストの結果、画面上の承認や取り込みの履歴 |
| **公開物の観測アーカイブ**（IPFS へのすべての公開と検証、Bitcoin のブロードキャスト、承認と内容の証明、Base への取り込み）。**アーカイブをクリア** するまで | — |
| 公開物の参照と公開者の関連付け | 開いていたカードや行 |
| 照合の判断と観測（アーカイブに保存） | 貼り付けたピアのアーカイブ、インポートした証拠のエクスポート、絞り込み、証拠エクスポートの比較、公開者のスナップショットの主張 |

再読み込みしたあとも、パイプラインや IPFS への公開の結果は、
[観測アーカイブ](12-ArchiveAndLeaderboards.md#公開物の観測アーカイブ)、
記録のライフサイクル、（Bitcoin の場合は）過去の Bitcoin アンカーの
証拠で見られます。続けるには、ウォレットを接続し直すか、ピン留め
サービスを設定し直してください。
